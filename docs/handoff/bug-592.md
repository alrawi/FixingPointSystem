## Goal

`src/pages/Runs.test.tsx` > "feed resilience" > "reconnects with Last-Event-ID after a dropped stream and fills the gap" fails intermittently with `expected 2 to be 1`. Find the real cause, fix the product or mock code if it is wrong, and make the test deterministic without loosening the assertion.

## Done and verified

1. Reproduction: with three busy loops on the 2 CPU sandbox the test failed 30 of 30 runs (expected 2, 3, or 4 to be 1). Plain it passes. The cause is a missing tick in the table of "Sessions per second", and there were three causes.
   - Mock (`ui/mock/server.ts`): the stream sent only the newest tick at each timer fire, but the clock of the run does not wait for the timer. A late timer skipped ticks (logged emits 8, 10, 11, 13). The contract says one event per tick. The mock now sends every tick since the last one.
   - UI (`ui/src/runs/useRunMetrics.ts`): a connection starts at the newest tick, and a tick can pass between the history read and the first event, but only a reconnect read the gap. The first event of every connection now reads the gap, the first connection included. This is a real, rare product race (one tick in 1000 ms periods when the history read is slow), found through the test.
   - Test: the table was asserted right after "Live", but the gap read answers some milliseconds after the first event of the new connection, so the table had a transient hole. The test now waits until the ticks of that read are on the screen (it records the read through the fetch spy) and then asserts, unchanged, that every row follows the next by one second. The run is also 600 ticks long, because under load a 40 tick run ended first and showed "Ended". The test timeouts are longer, which loosens no assertion.
   The UI did not reconnect twice, request the gap twice, or duplicate an event: the log shows one cut and one reconnect each time.
2. Regression tests, both fail on the old code and pass on the new: `mock/runs.test.ts` "sends every tick, in order, even when the timer of the stream fires late" (fails on the old mock) and `Runs.test.tsx` "fills the tick that passes between the history read and the first event of the stream" (fails on the old hook with 5 points instead of 6). Both use an injected clock and need no timing.
3. Loops of the single test (shell loop, one vitest process per run): before the fix 0 of 30 passed under load. After the fix 100 of 100 passed under load and 100 of 100 plain. An earlier version of the fix failed 3 of 100 under load because the wait for the gap ticks assumed they were still in the newest rows, and that is fixed.
4. `npm run test` (279 tests), `build`, `check:bundle`, `lint`, `typecheck`, and Prettier pass in `ui/`. `plan.py check` and `lint` pass.
