## Decisions taken in this package

- Two agent identities, `gate1-client` with `--side client` in the client namespace and `gate1-server` with `--side server` in the server namespace, each with its own run of the same configuration. The compiler gives every agent both sides of its pool slices, and one process lives in one namespace, so one identity cannot put its two sides on the two arms of the harness.
- The controller runs in the client namespace. The server agent dials it over a veth link between the client and server namespaces, so control traffic never crosses the captured arm.
- The mix uses `modules/http1` and `modules/dns`, copied from the tracked files, with one server port per mix entry, because two entries must not listen on the same transport and port.
- A threshold above 1 is allowed. The realism runner gets the smaller of the threshold and 1, and `gate1_report.py` compares every ratio with the full threshold, so a measured ratio of 100% can still be beaten by the negative proof.
- The suite writes `report.md` as Testing requires, plus `summary.json` for the negative proof.

## Pitfalls

- shellcheck 0.11 reports SC2329 for a trap function when the script ends with `exit "$rc"`. Ending with the last command under `set -e` avoids it.
- Run ids start with `cfg_`, because the orchestrator uses `store.RandomID`. The log entry asks for a CTL follow up.
- An exact match of captured and attempted sessions is flaky. One CI run captured 976 of 977 `dns` sessions, because two UDP queries that reuse one client address and source port form one session of the realism runner. The check now allows 1% fewer captured sessions and no extra session.
- Under sudo on a runner git refuses the checkout of another user, so the suite passes `-c safe.directory`.
