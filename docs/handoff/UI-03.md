## Goal

Edit test configurations through forms for network, profile, load, timeline, and criteria, and through a YAML view. Both views edit the same text, and the browser checks it against the JSON Schema of the contract with inline errors. The controller validates a stored copy through `validateConfig`. Every example test round trips through the editor without changes.

## Decisions taken in this package

- Round trip definition: text stays byte for byte until a form edits it; an edit goes through a `yaml` Document serialized with `lineWidth: 0`, which keeps comments, key order, quoting, and flow style of untouched nodes. A configuration loaded from the controller is JSON, so it shows as canonical YAML in schema key order and round trips as a value.
- `ajv` and `yaml` move from devDependencies to dependencies, because the editor ships them. The editor route loads lazily, so the initial bundle does not grow.
- The controller validates only stored configurations, so "Validate on controller" stores a new copy first when the text changed.

## Pitfalls

- `yaml` folds long lines at 80 characters by default and then differs from the source; always pass `lineWidth: 0`.
