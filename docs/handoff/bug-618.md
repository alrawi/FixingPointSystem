## Decisions taken in this package

The view was already right since RLM-24: each session has its own initial sequence numbers. The count was wrong because `messages.check` looked the tshark counts up by four tuple, which both connections share. The probe now reports the frame of every count and the check attributes the frame to a session with `SessionResolver`, the rule of the session table. A probe without frames (the stub) keeps the lookup by four tuple.

## Pitfalls

The plain view passed since RLM-24, so a test that only builds the view and reads the session table does not show the bug. The test must run the message count check.
