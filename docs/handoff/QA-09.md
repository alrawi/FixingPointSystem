## Decisions taken in this package

- The artifacts of the two failing CI runs could not be downloaded (the sandbox proxy blocks the blob host), so the cause comes from the job logs of 86 gate runs and from local runs. Both failing runs had fewer http1 sessions captured than attempted (1337 and 1339 of 1340), 16 of 86 runs had that, and 0 of the 70 others had a finding. A boundary cut cannot explain missing sessions.
- tshark 4.2.2 did not report anything in 24 local runs, nor in a capture with 259 reused sessions. The first CI run of the branch (42921139910) confirmed the cause: Zeek weird `premature_connection_reuse` in a session with two connections (1338 of 1340 http1 sessions). The rule counts only that weird in reused sessions; a tshark finding, any other weird, and a finding in a one-connection session still fail.
- The loop is `FPS_GATE1_REPEAT` in `run.sh`. The workflow step needs the variable, see the log entry.
- The corruption proof is called by `prove-threshold.sh`, because `mk/qa-gate1.mk` is a shared file.

## Pitfalls

- The sandbox shell guard refuses commands that mix git with heredocs or `source`; write files with the editor tools.
- Zeek is not installed here, so the Zeek side is tested only by the unit tests and by CI (run 42921139910 showed the weird and both proofs).
