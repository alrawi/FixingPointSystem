## Decisions taken in this package

- Three stages in three CI jobs, and a report job that reads their artifacts, so one stage cannot hide another and a stage without files fails.
- The mix scores the capture against the byte weights (`score-config.yaml`) whatever basis the controller ran.
- Waivers are explicit, named in the report, and lapse by themselves (modules) or by deleting one variable (basis). The verdict reads `PASS WITH WAIVERS`, never `PASS`.
- `hls` and `http1` share the row `http`, because nDPI cannot tell them apart. `aux` takes FTP data and RTP.
- The weights are chosen so that every row with large sessions sees more than 100 sessions, which keeps the Poisson noise below 2 points.

## Pitfalls

- The sandbox cannot build the Go controller (no module proxy), so the mix stage only runs in CI.
- The agent rejects a scenario parameter that the scenario does not declare (`scenario has no variable`). A unit test checks every parameter of `mix.yaml`.
- The run report counts the FTP data connection and the SIP media stream as sessions of their own, so estimates of bytes per session come from the scenario totals and need the factor of 2 for those two.
- A new CI run cancels the earlier run of the same ref (the concurrency group), so push only when the previous run is read.
