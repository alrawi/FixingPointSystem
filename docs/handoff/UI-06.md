## Goal

Show agents, their capabilities, reservations, and port assignments in the web UI. An agents list offers reserve and release actions, and component tests cover reservation conflicts that the API reports. The view uses only `GET /agents`, `POST /agents/{id}:reserve`, and `POST /agents/{id}:release` of the REST OpenAPI 0.8.0.

## Decisions taken in this package

- The view shows the ports that each agent offers and not an assignment of test ports, because the `Agent` schema has no such field.
- The view sends a reserve or release whatever the list shows and reads the list again after a 409 or 404, so the controller decides. The mock copies the controller: reserve is idempotent and refuses only offline and busy agents, release always succeeds.
- The contract names no status code for a refused reservation, so every problem is shown with its detail.

## Pitfalls

- The mock `GET /capabilities` and `GET /agents` serve one live agent list per server, and tests change it through `RunningMockServer.agents`.
- Tests set `pollMs` to 60 s so the list does not refresh before a click.
