## Goal

We build `tests/harness/netns.sh`, which connects a client namespace and a server namespace through a routing namespace that stands in for the device under test. End to end tests then run on any Linux CI runner without virtual machines. The script offers `up`, `down`, `exec`, and `capture`, with configurable prefixes, MTU, an optional VLAN, and optional NAT in the routing namespace.

## Remaining

The gaps below are known and outside the catalog deliverables.

- The harness is IPv4 only and turns IPv6 off in the namespaces. A later package can add `FPS_CLIENT_NET6` and `FPS_SERVER_NET6`.
- The client and server take one address each. HST-02 adds host pools on the client arm and may need a range option.
- The `all` capture mode uses the Linux cooked v2 link type of the `any` interface, so realism checks that expect Ethernet should record one arm.

## Blockers and open questions

None block the package. The questions below are for the owner.

- The VLAN case runs only in CI, because the agent container lacks the `8021q` module.
- The `qa` workflow touches `.github/workflows/` and the root `Makefile`, which the Testing page assigns to workstream packages, although the catalog lists only `tests/harness/` as the package path.

## Decisions taken in this package

- Every link and route lives inside the three namespaces, and veth pairs are created directly in them. The root namespace never changes, so `down` only deletes namespaces and state files.
- The interfaces have fixed names inside the namespaces (`eth0` at each end, `cli0` and `srv0` on the router), so `FPS_NETNS` only names namespaces and has no 15 character limit to respect.
- Captures always use tcpdump with `--immediate-mode` and a converter in the standard library. dumpcap writes pcapng directly but lost the final packets of a flow on stop, because it buffers in the kernel ring without an immediate mode.
- The temporary pcap file ends in `.part.pcap`, because the Ubuntu AppArmor profile of tcpdump permits writes only to files with a capture extension.
- Offloads are off by default (`FPS_OFFLOAD=0`) so captures show wire sized frames, and IPv6 is off so captures hold only test traffic.
- `up` cleans up a partial harness on any failure through an EXIT trap, so a retry starts clean.
- `make e2e` and `E2E_TARGETS` are new aggregates, as the Testing page announced for this package.

## Pitfalls

- `python3 -m http.server` inside a namespace waits for a DNS timeout before it listens, because `server_bind` resolves its own address. The self test overrides `server_bind`.
- tcpdump without `--immediate-mode` reports packets as received by the filter and writes none of them when stopped quickly.
- A process that `setpriv` drops to `nobody` cannot read the checkout on GitHub runners, so the self test runs a copy of `netns.sh` from its work directory.
