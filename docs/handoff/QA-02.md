## Goal

We provide one golden file convention for Rust, Go, and Python tests under `tests/golden/`. Each helper compares output with a testdata file, rewrites that file only when `UPDATE_GOLDEN=1` is set, and prints a diff that names the golden file on mismatch. Each helper has tests for match, mismatch, and update.

## Decisions taken in this package

- The root member glob matches only `spikes/` and `engine/`, so we add `"tests/golden/rust"` to `members` in the root `Cargo.toml`. That file is OPS owned, and the pull request flags the change. `Cargo.lock` gains the `fps-golden` entry.
- A member path that does not exist makes Cargo fail, so the `test-ops-workspace` probe in the `Makefile` now copies `tests/golden/rust` into its temporary workspace. That line is also OPS owned and flagged.
- The Rust crate has no dependencies. Its error type implements `std::error::Error` by hand instead of using `thiserror`, and its diff is a small LCS line diff.
- The Python helper is a plain module with a `golden` fixture. A consumer imports the fixture in its `conftest.py`, because `pytest_plugins` is rejected in a conftest below the rootdir.
- The Go helper has its own `.golangci.yml` with the linters that Coding Standards requires.
- Update mode applies only when `UPDATE_GOLDEN` equals `1`. Any other value compares.

## Pitfalls

- `golangci/golangci-lint-action@v8` has no `install-only` input and runs the linter at the repository root, where `./...` matches no module. The workflow installs the binary with `go install` instead.
- Cargo treats a missing workspace member as an error, so any new root member breaks `test-ops-workspace` unless the probe copies it.
