## Goal

After #712 (encryption check lost a session to client port 40000, SAP NI in Wireshark 4.2), audit every `tshark -d` use under `realism/` and fix any that a registered client port can steal from.

## Plan

- [x] 1. List the uses: `encryption.py` (fixed in #715), `messages.py`, `decrypted.py`.
- [x] 2. Move one session of each module fixture to client port 40000 and compare the reader and the message counts with the unmoved capture (tshark 4.2.2).
- [x] 3. Add a guard test.
- [x] 4. PR, CI green, review.

## Done and verified

- `decrypted.py` TLS ports (`-d tcp.port==P,tls`): a ClientHello is never rejected by the TLS dissector, so nothing falls through to the client port. 80 of 80 (http1) and 40 of 40 (http2) sessions read with client ports moved to 40000 one at a time.
- `decrypted.py` STARTTLS ports (`-d tcp.port==P,smtp|imap`): the server port decodes as the application protocol, which accepts the clear text start and then upgrades to TLS. 8 of 8 smtp and imap sessions read with a client port moved to 40000, with the same message counts in the view.
- `messages.py` (`-d tcp.port==P,<protocol>` on the plain text view): the same counts for http1, http2, smtp and imap with a client port on 40000.
- Only the encryption probe decoded a port as TLS for a session that starts in clear text. No code change was needed.
- Guard test `test_a_client_port_that_wireshark_registers_loses_no_starttls_session` (smtp, imap) in `realism/tests/test_decrypted.py`.
