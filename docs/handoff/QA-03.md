## Decisions taken in this package

1. **The baseline owns the policy.** Direction and tolerances come only from the baseline, so a result cannot loosen its own limits.
2. **Allowed worsening is `max(tolerance * abs(baseline), abs_tolerance)`.** The absolute part covers metrics whose baseline is zero, such as failed sessions.
3. **A missing metric fails, an extra metric is only listed.** A suite that drops a run must refresh its baseline in review.
4. **A host difference is a note by default.** `--require-same-host` makes it a failure for the nightly job on a fixed host.
5. **Tolerances live in the adapter.** Rates 10%, p50 15%, p99 25%, failures zero. The phase 0 repetitions varied about 2% in rate and 5% in p99.
6. **Ratios of interpreter to baseline rate.** They depend less on the host and carry the 25% criterion that ENG-05 checks.
7. **Baselines are generated, never hand edited.** A test regenerates the S1 baseline from the committed raw files.

## Pitfalls

1. `run-bench.sh` expects its binary under `target/` of the repository, so `bench-s1` drops `CARGO_TARGET_DIR` for the build.
2. `run-bench.sh` writes `spikes/s1-engine/results/<label>/`; commit that directory only when refreshing a baseline.
3. Shared CI runners are far too noisy for a 10% tolerance; never run real benchmarks there.
