## [2026-11-10] ingest | RLM-12 A current nDPI and a shared decrypted view in the realism runner

The realism CI now builds nDPI 4.14 and the runner has one decrypted view command. `realism/ci/ndpi.version` pins the release and the commit of its tag (`4.14 90090b9ae841fce67d00c52ac87e755dcea7c95f`), and `realism/ci/build-ndpi.sh` fetches that commit, checks the id, builds `ndpiReader`, installs it under `/opt/ndpi`, and links it into `/usr/local/bin` ahead of the `libndpi-bin` package. `install-tools.sh` calls the script last, so the `rlm` and `realism` workflows share it. We pinned a commit and not a tarball because a GitHub archive of a tag is not byte stable, and we built in the script and not in an `actions/cache` step because a cache step lives in a workflow, outside `realism/`. `NdpiClassifier` reads both CSV dialects (nDPI 4.2 separates with commas, 4.14 with `|`, chosen by the header line) and accepts the exit code 1 of `ndpiReader -h`.

`python3 -m realism decrypted --pcap F --labels L` decrypts the TLS sessions with tshark, writes their plaintext as plain TCP sessions (IPv4 and IPv6) with the addresses of the originals, and scores that view with the labels `L` and the parsers. `--plaintext upgrade` puts the plain start of a STARTTLS dialogue in front, without the STARTTLS command and its reply, `--view-port` moves the sessions to the port of their protocol, and `--sessions N` fixes the number of TLS sessions that the capture must hold. `realism/examples/decrypted/` has the labels of the four fixtures. With the real tools (nDPI 4.14.0, tshark 4.2.2) the command decrypted 80 of 80 TLS sessions of the http1 fixture, 8 of 8 of smtp, 8 of 8 of imap, and 40 of 40 of http2 (taken from `wp/MOD-06`), and nDPI named every view session `HTTP`, `SMTP`, `IMAP`, and `HTTP2`. nDPI 4.14 named 40 of 40 cleartext sessions of the http2 fixture `HTTP2`.

### Shared page notes

- Module workflows (`mod-http1.yml`, `mod-smtp.yml`, `mod-imap.yml`, and `mod-http2.yml` once MOD-06 merges): they install `libndpi-bin` themselves, which is nDPI 4.2.0. A job that runs the commands below needs nDPI 4.14 and calls `realism/ci/install-tools.sh` instead, or `realism/ci/build-ndpi.sh` when it installs its own tools (it needs `sudo`, `git`, and network access to GitHub, and it takes a few minutes). The `http2` job needs it for `HTTP2`. The three commands for the modules of this branch, to run from the repository root where `python3 -m realism` is importable (or after `pip install ./realism`), replace the `decrypted_check.py` calls:

  ```bash
  python3 -m realism decrypted --pcap modules/http1/fixtures/http1.pcapng \
    --labels realism/examples/decrypted/http1.labels.yaml --sessions 80 --parsers tshark
  python3 -m realism decrypted --pcap modules/smtp/fixtures/smtp.pcapng \
    --labels realism/examples/decrypted/smtp.labels.yaml --sessions 8 \
    --plaintext upgrade --view-port 587 --parsers tshark,zeek --zeek /opt/zeek/bin/zeek
  python3 -m realism decrypted --pcap modules/imap/fixtures/imap.pcapng \
    --labels realism/examples/decrypted/imap.labels.yaml --sessions 8 \
    --view-port 143 --parsers tshark,zeek --zeek /opt/zeek/bin/zeek
  python3 -m realism decrypted --pcap modules/http2/fixtures/http2.pcapng \
    --labels realism/examples/decrypted/http2.labels.yaml --sessions 40 --parsers tshark
  ```

  Each command exits with 0 on success, 1 when a session does not decrypt, the count is wrong, or the view fails a check, and 2 when a tool cannot run. Add `--view FILE` to keep the decrypted view and `--output FILE` for the JSON result. We ran the tshark variants against the committed fixtures and the http2 fixture of `wp/MOD-06`. Zeek is not installed in the sandbox, so the `--parsers tshark,zeek` variants of smtp and imap are untested here, and the smtp message and attachment check of Zeek (`modules/smtp/fixtures/zeek_check.py`) stays in the module, because the command scores only the parser errors of Zeek. The same switch applies to the `capture.sh` scripts of the four modules (call `python3 -m realism decrypted` with `cd "$root"` in front) and to `mk/mod-smtp.mk` and `mk/mod-imap.mk`, whose Makefile lines in the MOD-20 log entry call `decrypted_check.py`. The counts that `decrypted_check.py` printed per protocol (requests, SMTP commands, IMAP literals) are not part of the command. Then the three scripts and the one of `wp/MOD-06` can go.
- `realism/ci/install-tools.sh` and the apt hang (branch `ci/apt-hang`): this package left the two `apt-get` lines of the script alone. `build-ndpi.sh` has one `apt-get install` line of its own for the build dependencies (`build-essential git autoconf automake libtool pkg-config gettext flex bison libpcap-dev libjson-c-dev`), which the helper `tools/ci/apt-install.sh` should wrap as well. Once both branches have merged, `libndpi-bin` can leave the install line of `install-tools.sh`, because `/usr/local/bin/ndpiReader` shadows it, and the line `ndpiReader -h | head -1 || true` that follows the apt lines prints the Ubuntu reader before the pinned one is built.
- [Testing](Testing.md): the optional tests of the realism runner that need nDPI 4.14 skip on a machine with an older ndpiReader (`realism/tests/test_ndpi_http2.py` and `realism/tests/test_decrypted_fixtures.py`), and `test_ndpi_http2.py` fails instead of skipping on a runner of GitHub Actions that has one, so the pin cannot lapse unseen. Until `modules/http2/fixtures/http2.pcapng` is on `main`, the runner fetches it with `git fetch --depth 1 origin wp/MOD-06` (`FPS_H2_FIXTURE_REF` names another ref), and that fetch is not needed after MOD-06 merges.
