## [2026-11-10] ingest | AGT-12 port filter for captures and a real end to end capture

The agent accepts `StartCaptureCommand.port` and records only the sessions that it selects, for TCP and UDP. `fps_agent::portfilter` reads the port as, in this order, empty (every session), the name of a port of the plan (the sessions whose client or server host lies in a pool on that port, which is what the REST contract of `startCapture` requires), or a server port, a comma separated list, or a range (`53`, `80,443`, `8000-8999`), matched against the server port of the session for both transports. Anything else is `ERROR_CODE_INVALID_ARGUMENT`. The `filter` and `snap_length` fields stay refused. `tests/controller_e2e.sh` now captures through `POST /v1/runs/{id}/captures` on the real agent: a dns run with port 18681, with port 9 (a valid file with no packet), and with the port name `server0`, and an https run with `export_tls_keys` true (the file holds a decryption secrets block of type 0x0A with the TLS key log) and false (none). Each capture is stopped with `POST .../captures/{id}:stop`, downloaded, and checked against `Capture.files[]` for content type, size, SHA-256, and packet count, and parsed by a small reader in the script (and by tshark when it is installed). The [Agent](../Agent.md#port-filter) page describes the filter.

Decisions. First, the contract says the REST `port` is a port name and the catalog says "server port"; the agent takes both, with a name winning, so a client that follows the OpenAPI document and a client that asks for "port 53" both work. Second, the TCP taps live in `fps-runtime` and read `fps_capture::CaptureCell`, outside the paths of this package, so the filter acts when `StopCapture` joins the ring: it reads the synthesized Ethernet frames, finds where a session starts, takes the server end from its first frame, and drops the frames of other sessions. The reported `packets`, `bytes`, and `digest` describe the filtered file. Third, the ring still takes the sessions that the filter drops, so `max_bytes` and the ring bound count them.

### Shared page notes

- [Controller](../Controller.md): the lines that say a capture through the REST API fails with `501` against the real agent are stale. The agent accepts a port name of the plan and a server port, and `controller_e2e.sh` downloads captures. The controller sends the port through unchanged and does not check it against the plan, so an unparsable port reaches the agent and comes back as `INVALID_ARGUMENT` (HTTP 400 if the controller maps it so).
- [Testing](../Testing.md): the filter is tested by `tests/run_control.rs::a_capture_with_a_port_skips_the_sessions_of_other_ports` and the unit tests of `src/portfilter.rs` (`make test-agt`), and the controller e2e job (`make test-agt-controller`) runs the REST captures. The `controller-e2e` job installs no tshark, so the script uses its own pcapng reader and calls tshark only when it exists.
- Follow-up for the ENG workstream: a predicate on the flow in `fps_capture::Capture::begin` (or a per worker cell in `fps-runtime`) would keep the other sessions out of the ring, so the byte limit and the ring bound would count only what the filter keeps. The agent code needs no change when it lands, except that `Captures::start` hands the filter to the capture.
- Follow-up for the coordinator: the end to end script could not run in the worker sandbox, which has no Go toolchain access, so the PR's `controller-e2e` job is its first run.
