## [2026-11-10] ingest | AGT-18 The run_control capture flake and the lost ftp sessions

Both flakes had a cause that the tests did not name, and neither was a shared port or a shared namespace of the tests.

`a_fake_controller_changes_rates_and_reads_a_capture` stopped its first capture while the run went on at 220 sessions per second, and asserted `dropped == 0`. A session that is open when `CaptureCell::clear` and `Capture::stop` run keeps its recorder, ends after the writer thread has gone, and `Shared::drop` counts it in `sessions_dropped_queue` because `try_send` finds the channel disconnected. A temporary diagnostic showed every drop was `Disconnected` and none was `Full`, and three busy loops beside the test made 3 of 4 runs fail with `dropped: 1` or `2`. The test now pauses both entries, waits until `sessions.concurrent` is zero, and stops the capture at rest. `a_capture_that_loses_sessions_reports_them_as_dropped` shows that a really lost session (a ring file too small for the HTTP sessions) reaches `StopCaptureResult.dropped`, so the assertion keeps its teeth. The agent code did not change.

The ftp test lost 2 of 95 sessions because of one instance. `mixed_session` picks each data port with `rand_int(data_port_min, data_port_max)`, the plan seed makes the draws identical in every run, and the 200 port range of the test drew nine ports twice in 72 draws. When two instances that drew the same port overlap, both clients connect to the first listener, which accepts one connection and drops, and the kernel resets the other: the failed counters showed one `unexpected_reset` and one `aborted` on each side in every failing run, which is one failed instance. A temporary log of every bound and connected data port showed the port, with two `connect_ok` before one `accepted`. With the three tests in parallel and three busy loops beside them, the 200 port range failed in 11 of 69 runs, and the range 53000 to 62999, whose 72 draws are all different, passed 44 of 44 runs. The mutex is gone because the tests do not interact: the other tests only slowed the ftp instances until two of them overlapped.

A package for `engine/fps-runtime` could draw data ports without repeats across the concurrent instances of a worker, or let a data listener keep accepting until its own peer arrives. A package for `engine/fps-capture` could count the sessions that are open at the stop apart from the sessions that the full queue dropped, because `StopCaptureResult.dropped` says "packets that the capture missed" and today also holds the sessions that the stop cut off.
