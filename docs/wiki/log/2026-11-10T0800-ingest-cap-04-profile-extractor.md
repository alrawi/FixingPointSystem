## [2026-11-10] ingest | CAP-04 Profile extractor

We added `python3 -m capture profile`, which reads a capture or a sessions document (scrubbed or not, with or without payloads) and writes the `profile` object of a test configuration: the application mix with a weight per application on a sessions or a bytes basis, an arrival model for the whole run, and an arrival model and request and response size models for each mix entry. Applications come from the server port through a table of the module ports and `--app` rules, and sessions that no rule names stay out of the mix and are listed. Each model is the best of constant, exponential, uniform, lognormal, and Pareto by Kolmogorov Smirnov distance, written with the parameter names of the contract, and the report keeps the distance of every candidate. The command builds on the CAP-01 reader and checks the CAP-03 scrub record with the function that `scenario` uses, so a profile says whether its input was scrubbed and how many sessions the scrub dropped. On the committed fixtures the http1 capture gives 60 and 40 percent by sessions and 47.7126 and 52.2874 percent by bytes for plain and TLS HTTP, and generated runs with a configured 50, 30, and 20 percent mix come back exactly within the 2 point limit. We described the command, the output, the fit, and the limits in [Capture](Capture.md). The evidence is `docs/handoff/CAP-04.md` and `capture/tests/test_profile.py`.
