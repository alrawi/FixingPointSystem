## [2026-11-07] ingest | ENG-13 run time rate adjustment

The crate `engine/fps-sched/` now changes the target of a running schedule without a restart. `Schedule::rate_handle()` returns a `RateHandle`, one atomic cell that any thread may set and that the owning worker loads at every `drain`. The arrival process keeps its operational time and only the map to time changes, so the expected count is continuous across a change, with no burst that catches up and no gap. A rate of 0 pauses the schedule and a resume owes nothing. `RateControl` maps a scenario id to the handles of its workers and applies `update` (a total per scenario, divided in proportion to the current worker targets) and `scale` (a factor per scenario, as CTL-21 produces) completely or not at all. An unknown id, a repeated id, a kind mismatch, or an invalid value changes nothing. The tests run on a simulated clock and show new rates within 5% for Poisson arrivals and within 1% for constant arrivals after two changes, a KS test of the rescaled gaps across two changes, and thread safety under concurrent writers. The [Engine](../Engine.md#run-time-rate-adjustment) page describes the behaviour.

### Shared page notes

- [Implementation Plan](../Implementation-Plan.md) and the catalog: AGT-05 should register one `RateHandle` per worker rate under its mix entry name in a `RateControl` and call `update` for `UpdateRates`. The CTL-21 calibration loop can use `scale` with its factors, or send totals, which the agent turns into `update`.
- ENG-10 (`fps-runtime`): a client worker that sleeps while `next_due` is `None` (paused, or at the cap) must wake on its own about every 100 ms to see a new target. `next_due` already returns a time that is not after the clock while a change waits, so a worker that re reads it after a wake ticks at once. The runtime is not changed by ENG-13, because it is outside the paths of the package. A follow up for the runtime should add the bounded sleep and expose the handle of each worker rate.
- `UpdateRates` in CON-05 gives a total per mix entry for the whole agent, and `RateControl::update` implements that division. A mix entry whose workers are all paused divides equally on resume, which differs from the proportional rule only when all current targets are 0.
