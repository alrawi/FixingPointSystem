## [2026-11-09] ingest | CTL-29 rebuild the agent inventory after a restart

The controller now rebuilds the agent inventory from the PKI state at start. `pki.Authority.ValidIdentities` returns the sorted identities that hold a certificate which the CA issued, which revocation did not end, and whose `NotAfter` is still ahead of the authority clock. `agents.Manager.Seed` adds those identities as enrolled agents without labels, skips identities that the inventory already holds and identities outside the Id pattern, and returns the identities that it added. `wiring.New` calls `c.Agents.Seed(c.PKI.ValidIdentities())` once after it creates the manager, which closes the known gap of CTL-27: an agent with a valid certificate registers again after a restart with `agent_auto_enroll` off. A revoked identity, an identity with only expired certificates, and an identity with only an unused token are not seeded. Operator labels and reservations are still in memory only, so a restart drops them. `TestRestartRebuildsInventoryFromPKIState` covers enrollment, a restart from the same state directory, a revoked and an expired identity, and `TestSeed` and `TestValidIdentities` cover the two methods. The [Controller](../Controller.md#agent_auto_enroll-with-certificates) page describes the behavior.
