## [2026-11-12] ingest | RLM-19 The port collision rule in the realism runner

The parser error check of the runner (`realism/parser_errors.py`) now applies the port collision rule that QA-11 built into the Gate 2 suite. The kernel picks the client port of a session at random, and tshark binds about 900 TCP and UDP ports to a dissector, so a well formed session whose client port is one of them (UDP 41170 is Manolito, TCP 44322 the Performance Co-Pilot proxy) gets malformed packet findings from a dissector that does not fit its payload. A tshark finding is a port collision when the client port of its session is bound to a dissector for the transport of the session and the server port is not bound to the same dissector. Such a finding no longer counts: it stays out of `errors_total`, `parser_errors`, `malformed_packets`, the metric series, and the verdict, and the entry lists it under `not_counted` with `rule` (`port_collision`) and `dissector`. A finding of Zeek, a finding without a session, and a finding in a session whose client port is free count as before.

How it works: `ParserRunner` has a new method `port_bindings()`. `TsharkRunner` reads `tshark -G decodes` once per run (`parse_decodes`, moved from `mix_findings.py`), `ZeekRunner` returns no table, and `StubParser` takes a table for tests. The check asks each parser for its table and calls `port_collision(session, bindings)` for every finding that has a session. If tshark cannot print its table, the table is empty and every finding counts, so a failure of the rule makes the check stricter and never looser. Report format 0.18.0 (the next number after 0.17.0 of CON-28) adds three optional fields to the `parser_errors` entry: `not_counted` (the first 100 entries), `not_counted_total`, and `port_collision_ports` (the size of the table). The schema moved the finding to `$defs/parser_error`, which `errors` closes with `unevaluatedProperties: false` and `not_counted` closes with the two extra fields. The module job summary (`realism/ci/summary.py`) says `N findings not counted (port collision)` in the row of the parser error check. `realism/README.md` and [Realism](Realism.md) describe the rule and the format.

Evidence: `realism/tests/test_port_collision.py` (16 tests): a collision passes and is reported as not counted, a real malformed packet next to it still fails and counts 1, a table of five cases (no table, server in the same dissector, server in another, other transport, server only), a finding without a session, Zeek, the cap of 100 with the true total, the report against the schema (and an extra field refused), `parse_decodes`, the table read once, no table when tshark is absent, the command through `main` with a stand-in tshark, and one with the real tshark 4.2.2: a UDP session from client port 41170 to server port 40000 gives 5 `manolito` findings that pass as not counted, the same session from port 41171 gives none, and the same capture with a malformed DNS answer fails with exactly 1 counted finding and the same number not counted. `realism/tests/test_parser_errors.py` has a stand-in tshark that answers `-G decodes`. The whole `realism/tests` run gives 829 passed and 9 skipped , and `ruff`, `mypy`, and the plan checks pass. The report version in the tests moved from 0.17.0 to 0.18.0.

Findings:

- The controller embeds a byte copy of the report schema (`controller/internal/report/schema/realism-report.schema.json`), and its Go test `realism_test.go` fails when the copy differs. Until the copy is refreshed, the controller also refuses a 0.18.0 report that carries `not_counted`, because its old schema closes the entry. The copy and `ui/src/api/schema.d.ts` are outside the paths of this package, so this pull request does not touch them. The coordinator refreshes both as RLM-15 did (see the Shared page notes), and the controller job and the ui job stay red until then.
- The rule hides a real fault when it lies in a session whose client port collides, as it did in QA-11. The finding stays in `not_counted`, and the job summary and the Gate 2 report print the count, so a person sees it. A narrower rule (the layer of the finding must be the dissector of the port) does not work, because the names of `tshark -G decodes` (`pmproxy`) and the protocol of the faulty layer (`pcp`) differ.
- The rule uses the default table of tshark. The decrypted view (`python3 -m realism decrypted`) decodes the server ports of its labels as TLS with `-d`, which the table does not know, so the rule judges a server port there by its default binding. No case where this matters is known.
- The module realism jobs (`realism/ci/module-realism.sh`) apply the rule through the runner and need no change. I could not run them here (no root, no Zeek, no `ndpiReader`).

  > A fixture score can list a parser finding as not counted. The operating system picks the client port of each session at random, and tshark decodes the traffic of about 900 TCP and UDP ports with the dissector that is bound to the port (UDP 41170 is Manolito, and TCP 44322 is the Performance Co-Pilot proxy). When a session of your module uses such a port as its client port, tshark reports malformed packets for payload that is well formed. The runner leaves a tshark finding out of the count when the client port of its session is bound to a dissector for the transport and the server port is not bound to the same dissector. The `parser_errors` entry of the report lists it under `not_counted` with the rule `port_collision` and the dissector, and the job summary of a module says `N findings not counted (port collision)`. A finding that is not counted does not change `errors_total` or the verdict. You do not change your traffic or your labels for it, and a recording that you make again draws another client port. Findings of Zeek, findings in a session whose client port is free, and findings that belong to no session always count, so a malformed message of your module still fails the check. A runner older than report format 0.18.0 counts these findings, so score with the runner of the checkout that you build against (`realism/README.md`, Parser errors).
