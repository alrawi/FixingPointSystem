## [2026-11-09] ingest | AGT-07 module settings, side label, and client default in the agent

The agent now applies `ModuleRef.settings`, registers its UDP session series through `fps_stats::SessionCounters`, and counts the client side in its criteria. `modules::NativeFunctions::for_modules` takes the module entries of the plan and the module directory. For `dns` it resolves `zone_file` against `<modules dir>/dns`, refuses a path with `..` and any path whose canonical form lies outside the module directory (CON-11 allows no path outside it), and builds the server from that zone with `Dns::from_settings`. Settings that the agent cannot apply, for a module without native functions here or one whose functions take none (`http1`), end `prepare` with `InvalidArgument` instead of being skipped, because a silent skip would measure another test. `src/udp.rs` registers its series with `SessionCounters` and the side of the worker, as `fps-runtime` does for TCP. A snapshot of a run, in standalone mode and toward the controller, now holds the client and the server series of the process, because the side label keeps them apart; before, the agent sent one side because the series had no label. `criteria::evaluate_for` counts one side, which is the client side, or the server side for a process without client workers, and `evaluate` is the client case.

Evidence: `cargo test -p fps-agent` passes locally, with `cargo clippy -p fps-agent --all-targets -D warnings` clean. `tests/standalone.rs` runs a plan with the dns module copy and `zone_file: zones/corp.zone`; it passes because the lookups for `www.corp.test` are answered, and the same plan without the setting fails with no succeeded session. A setting with `..`, an absolute path outside the module directory, or a missing file ends the run. The unit tests in `src/modules.rs` cover the path rules, a symbolic link out of the directory, and the refusals. `src/criteria.rs` shows both sides in one snapshot with the client default and the server choice, and `src/udp.rs` and `tests/run_control.rs` show the side label on every series and both sides in a snapshot. `tests/controller_e2e.sh` adds the run of a dns zone test through the real controller, with a control run without the setting that must fail; the controller e2e job runs it through `make test-agt-controller`. It ran only in CI, because the Go modules cannot be downloaded in the sandbox of this package.

Findings:

- The wire `Criterion` has no labels, so a criterion cannot name a side in the agent, although the test configuration schema has `where` and the controller evaluator honors it. The agent default matches the controller default. A contract change would be needed to evaluate a named side in the agent, and the controller already evaluates the final verdict.
- `contracts/examples/tests/dns_zone.yaml` names `dns/resolve`, which only the example `dns` module has. Its manifest catalog differs from the crate `fps-module-dns`, so that module has no native functions in the agent and the agent now refuses its settings. The e2e test therefore follows the shape of `dns_zone.yaml` with the first party module and `dns/lookup_a`, on loopback pools. Pointing the example at `dns/lookup_a` of the first party module would need a CON change.
- The e2e script copies `modules/dns` without `native/` and `tests/` and adds one zone file, so the agent directory and the controller registry hold the same tree. The controller had not installed a first party module through the REST API before, so a refusal there shows in the CI log of the controller e2e job.
- `docs/wiki/Agent.md` records that sums over all labels of an agent snapshot line count each session of a two sided process twice. Readers of the JSON lines must select `side`, as `tests/standalone.rs` does now.
- The agent keeps its own `CaptureCell` for now. AGT-10 switches it to `fps_capture::CaptureCell`.
