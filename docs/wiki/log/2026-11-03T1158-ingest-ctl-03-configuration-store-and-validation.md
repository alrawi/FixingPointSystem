## [2026-11-03] ingest | CTL-03 Configuration store and validation

We added the package `controller/internal/store` and a Configuration store section at the end of the [Controller](Controller.md) page. It stores test configurations as canonical JSON in SQLite behind the interface `store.Repository`, using the pure Go driver `modernc.org/sqlite`, and serves `POST /v1/configs`, `GET /v1/configs/{id}`, and `POST /v1/configs/{id}:validate` through `store.Handler`, which embeds `api.Unimplemented`. Create accepts JSON and YAML and checks the body against `contracts/schemas/test-config.schema.json`, and a body that breaks the schema gets a 422 problem whose errors name each failing field with a JSON Pointer. Validate adds cross references, scenario references through `store.ModuleCatalog`, agent capacity through `store.AgentInventory`, and a dry run of the test compiler. Every example under `contracts/examples/tests/` stores and validates, and each fixture under `controller/internal/store/testdata/` fails at the field that its first line names. The module `controller/go.mod` gained `modernc.org/sqlite` v1.46.1, `github.com/santhosh-tekuri/jsonschema/v6` v6.0.2, and a direct `golang.org/x/text`, and its go directive now reads `go 1.24.0`. The evidence is `make lint-ctl test-ctl` and `docs/handoff/CTL-03.md` on the branch `wp/CTL-03`.

## Shared page notes

The coordinator may apply five notes.

1. The Layout table of [Controller](Controller.md) can gain the row `internal/store/` with the purpose "Stores and validates test configurations and serves the /v1/configs operations".
2. The controller command does not mount the REST layer yet. When a package wires it, `cmd/fps-controller` opens the store with `store.Open(ctx, path)`, builds `store.NewHandler(repo, store.Options{Modules: registry, Agents: agents, Logger: logger})`, and passes the handler to `api.New`. The configuration file then needs a key for the database path, such as `store_path`, in `internal/app`. Until CTL-04 and CTL-06 land, `Modules` and `Agents` stay nil, and the validate report says that it skipped those checks. The registry and the agent manager satisfy the interfaces with the methods `Scenarios(ctx) ([]compiler.Scenario, error)` and `AvailableAgents(ctx) ([]compiler.Agent, error)`, or through small adapters in the command.
3. The workflow `.github/workflows/controller.yml` does not run on changes under `contracts/`, so a schema change alone does not run the test that compares the embedded copy in `controller/internal/store/schema/` with the contract. Adding `contracts/schemas/**` to its paths would close that gap.
4. CTL-04 and CTL-06 also change `controller/go.mod`. Our additions are the three `require` lines above, the indirect lines of the SQLite driver (`modernc.org/libc`, `mathutil`, `memory`, `github.com/dustin/go-humanize`, `github.com/ncruces/go-strftime`, `github.com/remyoudompheng/bigfft`, `github.com/mattn/go-isatty`, `golang.org/x/exp`, `golang.org/x/sys`), upgrades of `golang.org/x/mod`, `sync`, and `tools`, and the go directive `go 1.24.0`. The merge train resolves a conflict there with `go mod tidy`.
5. [Testing](Testing.md) can list `controller/internal/store/testdata/invalid/` and `unresolved/` as the fixtures of the configuration validation, and [Home](Home.md) can mark CTL-03 as ready for review.
