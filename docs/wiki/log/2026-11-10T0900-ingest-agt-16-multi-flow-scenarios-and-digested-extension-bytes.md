## [2026-11-10] ingest | AGT-16 Multi flow scenarios and digested extension bytes in the agent

The agent runs scenarios with several flows. `assemble.rs` no longer refuses them, and `assemble::check_flows` refuses at prepare a scenario with several flows of which any is UDP and a scenario whose entry flow is `spawned`. `modules.rs` compiles every scenario with `Scenario::parse_instance`, so `spawned` flows and `spawn` load, and registers `fps-module-http2` as a stateful value (`Http2::default()`, cloned per session). The digest pass of `modules.rs` now reads `extension.wasm` once and keeps the bytes, and `ExtensionSet::load_module_bytes` compiles those bytes, so a file that changes after the digest check is never read. `tls::build` registers every client profile with `TlsProfiles::with_client_factory` (one connector per session, after one connector built at prepare to validate the profile), the server profiles issue tickets again, and `assemble` sets `FlowRef::port` to the port of the client pool (client workers) or the server pool (server workers), so the `tls.*` series carry the port names of the plan. The agent also offers a client profile `mail-client` (`firefox-139` without ALPN) and the server profiles `server-tls13-h2` and `server-tls13-noalpn`, built in `tls.rs` from what `modules/tls` has on main. The evidence is `docs/handoff/AGT-16.md`: `tests/first_party.rs` runs the ftp scenario `mixed_session` (a control flow and three spawned data flows) through `run`, `tests/extensions.rs` swaps `extension.wasm` between the digest and the compile through the hook of `modules::load_with` and the plan loads with the digested extension, `tests/tls.rs` checks the port labels, the per session connectors against a ticket issuing server, and the new profiles, and `controller_e2e.sh` gained an ftp run through the real controller and agent (its first run is the CI job `controller-e2e`). We updated [Agent](../Agent.md).

### Shared page notes

- TRN-15 (`modules/tls/`, runs in parallel, not edited here). When it has merged, switch `tls::mail_client_profile` and `tls::SERVER_SPECS` in `engine/fps-agent/src/tls.rs` to the registry of the TLS module under the names that TRN-15 chose. The agent uses `mail-client`, `server-tls13-h2`, and `server-tls13-noalpn`, so a TRN-15 that names its mail client profile differently needs one rename (`MAIL_CLIENT`) and the scenarios that use it. The agent builds the three profiles itself until then: `mail-client` is `firefox-139` with `alpn` cleared, `server-tls13-h2` selects `h2` and then `http/1.1`, and `server-tls13-noalpn` selects none. The agent does not claim a JA4 for `mail-client`.
- MOD-06 (`modules/http2/manifest.yaml`). The registry holds `http2`, but the manifest is not on main yet, so the unit tests of `modules.rs` skip `http2` while `modules/http2/manifest.yaml` is missing (`registered_with_manifest`, which asserts that only `http2` may lack a manifest). After MOD-06 merges, those tests cover `http2` with no change, and the exception in the helper can go. If the manifest catalog differs from `fps_module_http2::FUNCTIONS`, `for_modules` leaves the module without native functions and notes it, which the unit test `first_party_manifests_get_their_native_functions` then reports.
- [Testing](../Testing.md): the `test-agt` row can list `tests/first_party.rs` (ftp instance), `tests/extensions.rs` (swapped extension), and `tests/tls.rs` (port labels, mail client, h2 and no-ALPN servers). The controller e2e row can list the ftp run.
- [Modules](../Modules.md): the ftp section can say that the agent runs the ftp scenarios as instances since AGT-16 (the tests of this package run `mixed_session`), and the http2 row can say that the agent registers the native functions.
- `engine/fps-agent/Cargo.toml` gained `fps-module-http2`, so `Cargo.lock` gained one entry in the dependency list of `fps-agent`.
- Follow up for `fps-flow` or the agent: `load_module` reads `manifest.yaml` twice before the digest pass (`Manifest::load`, then `manifest_version`), so the manifest has the same check-then-use gap that `extension.wasm` had. A `Manifest` reader over bytes, fed from the bytes that the digest pass keeps, closes it. It is outside the acceptance of AGT-16.
- Follow up for a runtime package: a scenario with several flows and a UDP flow (SIP with RTP) stays refused. `assemble::check_flows` is the place to lift the check once `InstanceEnv` opens datagram sockets.
- Controller: `controller_e2e.sh` installs `ftp` beside `content`, and the controller accepted the plan in no local run, because the sandbox cannot build the Go controller. If the controller rejects a multi flow scenario, the failure shows in the CI log of `controller-e2e`.
