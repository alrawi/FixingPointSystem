## [2026-11-17] ingest | HST-04 DHCP for user space backends

HST-04 (issue #574) adds a DHCPv4 client per host to `fps-hosts`, so the hosts of a pool whose slice has `dhcp4` (CON-34) obtain and renew their addresses on a user space backend. The new module `dhcp` has a message codec, Ethernet, IPv4, and UDP framing, the state machine of one client (discover, request, bound, renew at T1, rebind at T2, start over), `LeaseTable` (the leased addresses of a slice), and `DhcpHosts`, which runs the clients of a slice on one `FrameIo` queue. `HostPool::dhcp(name, count, mac_base)` is the constructor for a pool without a prefix, `NeighborTable::add_leased` teaches the ARP responder the leased addresses, and `PortSpec::new` refuses a DHCP pool with an error that names `dhcp4`. [Hosts](Hosts.md#dhcp-leases) describes the design, the choices where RFC 2131 leaves room, and the tests.

Acceptance, "hosts of a pool configured for DHCP obtain and renew addresses in the namespace harness". `tests/dhcp_harness.rs` brings up the QA-01 harness with a DHCP server in the router namespace and eight hosts on the client arm through AF_XDP. All eight lease `10.201.0.100` to `10.201.0.107`, renew by unicast at T1 of a 6 second lease with the same addresses, and release them. The router resolves each leased address to the MAC address of its host. The same test runs in the `rust` job of `ci.yml` through `sudo -n`, and fails instead of skipping when `CI` is `true`.

Decisions.

- A DHCP pool is a `HostPool` with a flag and no prefix, built by `HostPool::dhcp`, and not a second type. `MacAllocator::claim`, `NeighborTable`, and the agent code that holds a `HostPool` keep their signatures, and every static address call answers "no address" for it.
- The lease table is plain data that the thread of the queue owns and clones for its consumers, with a generation number that moves when the set of addresses changes. The `Responder` stays immutable, because the workers of all queues share one, so a loop builds a new table and responder from a snapshot when the generation moves.
- The client takes the first offer, sets the broadcast flag before it has an address, and renews by unicast to the MAC address of the last reply. Where the server cannot be reached that way, the broadcast rebinding at T2 recovers the lease. The client does not probe with ARP and never declines.
- Time and randomness are inputs. The state machine reads no clock, and the seed derives the transaction identifiers and the jitter, so a run repeats (Coding Standards, rule 5).
- No new dependency. The codec is written for this crate, and the dev dependency `socket2` gains the feature `all` for `bind_device` in the test server.

Findings.

- A frame that a kernel sender puts on a veth pair carries only the partial UDP checksum of the pseudo header (checksum offload), and an AF_XDP receiver sees that value. The first version of the parser checked the UDP checksum, dropped every reply of the test server, and the clients discovered forever. The parser now checks only the IPv4 header checksum.
- The unicast renewal makes the test server answer to the leased address, so the router resolves that address by ARP. The test therefore proves in the harness that the responder answers from the lease table, and the neighbor table of the router shows the MAC address of each host.
- `PortSpec::new` accepted a pool without a prefix and set up a port with no local route. It now refuses a DHCP pool, because the kernel backend has no DHCP client and needs the addresses at setup.

- Module Development: no change, because no manifest field, scenario action, template function, or module rule changed.
- Agent follow-up (needs a dispatch, paths `engine/fps-agent/`, depends on HST-04 and on the user space transport that opens the port queues). The agent refuses `dhcp4` at Prepare today, and the capture filter of a DHCP port keeps every session. The exact changes follow.
  1. `src/assemble.rs`, `pool_of`. Replace the refusal with `HostPool::dhcp(&slice.name, slice.pool_count, opt(&slice.mac_base))`, mapped to `RunError::rule(format!("host pool {}: {e}", slice.name))`. The slice has no prefix and no gateway, so nothing else of `HostPool::parse` applies. `HostPool::is_dhcp()` tells the later code which pools lease.
  2. Prepare, for a port that carries a DHCP slice. A kernel backend fails Prepare with an error that names `dhcp4` (`PortSpec::new` already returns one, `port {port}: invalid specification: host pool {pool} leases its addresses (dhcp4)`, so the agent can pass it through). A user space backend claims one `MacBlock` per worker range with `MacAllocator::claim(&pool, range)`, makes one `DhcpHosts::new(&pool, &block, &DhcpConfig { seed: plan seed, vlans: the port VLAN ids, ..Default::default() }, now)` per worker queue, and runs the loop `NeighborService::poll` then `DhcpHosts::handle_frame` for each passed frame, then `DhcpHosts::send_due`, until every `leases().is_complete()` or a timeout (60 seconds is a safe start, because the clients of 20,000 hosts start over one second of random delay and send at most 256 new messages per call). On a timeout Prepare fails with an error that names `dhcp4`, the pool, and `leases().bound()` out of the count.
  3. `Pools::addresses(pool, range)`. For a DHCP pool read `LeaseTable::addr_of(i)` from the table of the slice instead of `ipv4_addr(i)`, which returns `None`. Keep one `LeaseTable::new(slice_range)` per pool and call `merge(&worker_table)` for each worker table, as the table of the slice is what `NeighborTable::add_leased(&pool, &macs_of_slice, &table)` and the filter need. `router_of(i)` is the gateway of host `i`.
  4. `src/portfilter.rs`, `port_nets`. A DHCP pool adds the leased addresses of the slice, and its port is no longer `leased` once the table is complete. The cheapest form is a new `Kind::Leased(LeaseTable)` (or `HashSet<Ipv4Addr>`) variant that keeps a session when `table.index_of(client_ip)` or `index_of(server_ip)` is `Some`, which costs one hash lookup per frame. `LeaseTable::host_prefixes()` (prefixes of length 32 in address order) and `subnets()` fit the existing `Net::V4(Ipv4Prefix)` list, but a scan over 20,000 prefixes per frame is too slow, so use `subnets()` there if the lookup form is not wanted.
  5. After Prepare. The lease table can change (a NAK, a lease that ends). Compare `leases().generation()` on each turn, rebuild the `NeighborTable` and `Responder` when it moved, and decide with the coordinator whether a lost address of a running host is a run error or whether the host drops out of selection. A renewal for the same address leaves the generation alone, so the common case costs nothing.
  6. `src/capabilities.rs`. No change. The version of the agent protocol is unchanged, because CON-34 already added `Dhcp4` to `HostPoolSlice`. The agent tests of CON-34 (`a_dhcp_pool_fails_with_an_error_that_names_dhcp4`, `a_plan_with_a_dhcp_pool_fails_before_any_pool_is_used`, and the `portfilter` test that expects a leased port to keep everything) change with the follow up.
  7. Server hosts stay static. Clients still compute the addresses of the servers from the prefix of the server pool.
