## [2026-11-18] ingest | TRN-28 OS profiles in the own stack

TRN-28 maps the OS profiles of the Transport page (windows11, linux6, macos14) onto the SYN and the SYN-ACK of the own stack: the IP TTL, the MSS, the window field, the window scale, which of window scaling, timestamps, and SACK a side offers, and the option order. The kernel backend cannot write the option order of windows11 and macos14; the own stack writes every row of the table.

- `profile.rs` has `OsProfile` (`builtin`, `validate`, `style`, `option_names`) and the constants `WINDOWS11`, `LINUX6`, `MACOS14` as static data, so the crate has no new dependency. `wire.rs` has `Style` (TTL and SYN option order), `SynOption`, `encode_styled`, and `options_len_styled`; `encode` and `options_len` keep their signatures and the old bytes. `host.rs` has `Host::with_profile`, and `OwnConfig` has `client_os_profile` and `server_os_profile` (both `None` by default, so a side without a profile is unchanged).
- A profile wins over `OwnConfig::window_scale`, `timestamps`, and `sack`. The MSS only lowers to the link, as `TCP_MAXSEG` does. The SYN window is lowered to the receive buffer. A SYN-ACK has the order of the profile and leaves out what the peer did not offer, with the NOPs that belong to it. Linux 6 keeps the kernel order writer that the stack had.
- The example `os_profile_capture OUTDIR [PROFILE...]` writes one pcapng per profile. In strict mode (`python3 -m realism score --os-profile NAME --client-hops 0 --server-hops 0 --transport-strict`) the `transport_behavior` entry passed with no failure and no deviation for all three profiles, and each capture scored as the next profile failed it. `handshakes.py` agrees on every value except the SYN-ACK TTL, which it expects one lower (the routing hop of the namespace test).

Tests: `tests/profile_table.rs` (3, reads the table of Transport.md), `host/profile_tests.rs` (13, the bytes of each SYN and SYN-ACK written out by hand, TTL of the ACK and of a reset, MSS at three MTUs, precedence over the option fields, shifts), `wire.rs` (5, the ordered writer), `profile.rs` (3), and one `tests/own.rs` test that runs each profile through `SessionIo` with a transfer in both directions and reads the frames. `cargo test -p fps-tcp-own`: 177 unit tests, 25 in `tests/own.rs`, 3 in `tests/profile_table.rs`.
