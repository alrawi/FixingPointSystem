## [2026-11-10] ingest | CAP-03 Scrubbing and provenance

We added `python3 -m capture scrub`, which rewrites a CAP-01 sessions document so that it holds no real addresses, user names, passwords, tokens, cookies, or email addresses, and writes a `scrub` record into it. Credentials get synthetic values of the same length and character classes, addresses go into 192.0.2.0/24 and the next documentation ranges (IPv4) and 2001:db8::/32 (IPv6), emails become `userN@example.test`, and one value gets one replacement across the capture. The rules cover HTTP Basic, Bearer and Digest, cookies, token headers, query, form, JSON and XML parameters, JWTs and common API key formats, URL credentials, SMTP and IMAP SASL (PLAIN, LOGIN, CRAM-MD5, XOAUTH2), IMAP LOGIN, POP3 USER and APOP, and FTP USER, PASS and the PORT and 227 addresses. `--hostnames`, `--hostname`, `--redact`, `--redact-file` and `--drop-port` cover what the rules cannot know. The scenario generator now takes `source: capture`, `scrubbed: true`, and the consent note only from an intact scrub record, so `scenario --consent` and `--scrubbed` are gone. The contract's provenance object has no field for the capture digest, the rule versions, or the date, so the manifest `notes` carry them in one sentence and the sessions document holds the full record. A seeded capture with 44 known secrets leaves none in the sessions JSON, in any payload, or in the generated module, searched raw, percent decoded and Base64 decoded, and the module validates. The 608 sessions of the module fixtures scrub and generate valid scenarios. The payload byte count changed by -1.0 percent on the seeded capture and by 0 to 80 bytes on the fixtures. We described the command, the rules, the replacements, and the limits in [Capture](Capture.md). The evidence is `docs/handoff/CAP-03.md` and `capture/tests/test_scrub.py`.

### Shared page notes

- [Testing](Testing.md): `make test-cap` now also runs `capture/tests/test_scrub.py`, which scrubs the six module fixture captures (about 11 seconds) and needs no root or network.
- [Implementation Plan](Implementation-Plan.md): CAP-03 is done. Binary protocols are not parsed (DNS wire names, TLS handshakes), so the scrubber reports the bytes it only swept and offers `--drop-port`. A capture of real users still needs a person to read the output before it is published.
- Contracts: the provenance object of the module manifest has only `source`, `consent`, `scrubbed`, and `notes`. If the owner wants the capture digest, the scrub rules with versions, and the date as fields, that is a contract change for a CON package. Until then they live in `notes` and in the `scrub` record of the sessions document.
- [Coding Standards](Coding-Standards.md): the CAP-02 options `scenario --consent` and `--scrubbed` changed meaning (they now exit with an error), which only matters to a script that used them.
