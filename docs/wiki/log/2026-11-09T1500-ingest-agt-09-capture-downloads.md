## [2026-11-09] ingest | AGT-09 capture downloads in the agent

The agent serves `fetch_capture` of CON-13. The session loop checks the command, answers with the size, digest, and chunk size of the finished file, and then spawns an upload task that opens `UploadCapture` on the tonic channel of the same session (so the same TCP connection and mutual TLS identity), repeats the transfer id and the session token, and sends chunks of at most 256 KiB in ascending offsets from `start_offset`, ending with `total_bytes` and the digest of `StopCaptureResult`. Unknown ids answer `NOT_FOUND`, a running capture `FAILED_PRECONDITION`, an offset beyond the size or a bad transfer id `INVALID_ARGUMENT`, and a second transfer `RESOURCE_EXHAUSTED`. A new flag `--capture-retention SECONDS` (default 86400, 0 keeps every file) deletes finished capture files after that time, never one with a transfer in flight. The [Agent](../Agent.md#capture-download) page describes it.

### Shared page notes

- [Testing](../Testing.md): the download is tested in `tests/run_control.rs` (a fake controller downloads a real capture in two parts, resumed at an offset after a broken call, and checks the SHA-256 against `StopCaptureResult`) and in the unit tests of `src/control.rs` (`a_transfer_reads_the_file_from_an_offset_and_refuses_what_it_must`, `a_capture_that_runs_cannot_be_downloaded`, `the_retention_deletes_old_files_and_spares_a_transfer_in_flight`, `without_a_retention_no_file_is_deleted`). Both run under `make test-agt`.
- [Controller](../Controller.md) line "The Rust agent answers `UNIMPLEMENTED` until AGT-09" and [Contracts](../Contracts.md) line "answers `ERROR_CODE_UNIMPLEMENTED` until AGT-09" are stale now: the agent serves `fetch_capture`.
- Gap between the controller and the agent that blocks a real end to end capture: `POST /v1/runs/{id}/captures` requires a non-empty `port` (the OpenAPI contract, and `captures.Service` rejects an empty one), while the agent refuses any non-empty port with `UNIMPLEMENTED` (AGT-05, "the agent captures sessions and cannot tell the ports of a plan apart"), which the controller reports as 501. So no capture starts through REST against the real agent, and `controller_e2e.sh` has no capture step. A fix is a small package: either the agent accepts a plan port and captures all its sessions (it records more than the port, which AGT-05 chose not to do), or the controller sends an empty port to the agent. Once one of them lands, the script can add start, stop (the download stops it), and `GET /v1/runs/{id}/captures/{capture_id}` against a `dns` run, since the agent captures UDP sessions only.
- The retention clock starts when the agent wrote the file. The controller should download soon after the capture ends, and a resume after the retention gets `NOT_FOUND`, which the controller treats as "no file".
