## [2026-11-09] ingest | AGT-13 First party native modules in the agent

AGT-13 replaces the two fields of `NativeFunctions` with one registry in `engine/fps-agent/src/modules.rs`. A table maps a module name to the function catalog of its crate and a constructor, and it holds `http1`, `dns`, `content`, `smtp`, `imap`, `pop3`, and `ftp`. A module whose native functions take no settings needs one line, and `dns` keeps its constructor for `zone_file`. `for_modules` takes the set of modules with a WebAssembly extension, as the AGT-11 note asked, so the registry adds no "no native functions" note for them and still refuses their settings. The agent also registers a module that a plan module requires and the plan omits, because the controller lists only the modules of the mix scenarios: an smtp plan names smtp and never `content`, and without this the `content.email` calls of every mail scenario fail in the agent. `tests/first_party.rs` runs an smtp, an imap, and a pop3 scenario through `run` with such a plan, and fails when `content` is removed from the registry. The unit tests resolve every function of every first party manifest. `tests/controller_e2e.sh` installs `content` and `smtp` in the controller and the agent and runs `smtp/relay` through the real pair. We updated [Agent](../Agent.md).

FTP is registered, but its scenarios do not run: the agent refuses scenarios with more than one flow, and `fps-runtime` has no worker that drives a `ScenarioInstance`.
