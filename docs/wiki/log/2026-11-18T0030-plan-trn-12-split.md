## [2026-11-18] plan | TRN-12 split after decision record 0014

Decision record [0014](../../decisions/0014-user-space-tcp-stack.md) chose the own stack of TRN-18 for the AF_XDP backend. The vetting agent accepted it under [D13](../../decisions/0013-autonomous-coordination.md) on 2026-11-17, after three edits. It also asked for six adjustments to the split of TRN-12 that the record proposed, and the coordinator applied them:

- A new first child, TRN-21, moves the own stack into `engine/fps-tcp-own/`, a crate without smoltcp. An agent that uses the own stack then does not link smoltcp, and the stack and the harness get separate paths.
- TRN-23 (loss recovery), TRN-24 (TCP options), and TRN-25 (congestion control) edit one state machine, so they run in sequence. Each has a numeric acceptance against the kernel stack over the same lossy link of TRN-22.
- TRN-27 runs the own stack on AF_XDP queues early, as the first real evidence for tier T1.
- TRN-31, which sets `TRANSPORT_AVAILABLE`, goes last and depends on TRN-23 to TRN-27. The flip makes AF_XDP automatic on every host with native XDP, and a stack without congestion control must not become the default. Because a package stays inside one workstream, the agent and controller changes became AGT-24 and CTL-54, which land first behind the flag.
- TRN-29 adds UDP over `FrameIo` and TRN-30 adds IPv6, because the own stack is IPv4 TCP only and no Phase 3 package covered either. Dropping them from v1 is a scope decision for the owner.
- TRN-22 reports a missing `sch_netem` on the hosted runner instead of installing packages, and TRN-25 records the smoltcp version and source file of any ported code.

Two further changes:

- SPK-05 runs the fallback spike of 0014 early.
- TRN-12 becomes the closing end to end package: http1 passes realism CI on the AF_XDP backend.

The TRN workstream gains the paths `engine/fps-tcp-own/` and `engine/fps-udp-own/`.

The owner keeps two questions from 0014. The first is whether tier T2 still needs F-Stack. The second is whether the T1 target of 2,000,000 sessions per agent holds: that is 4,000,000 sockets and about 0.9 GB of connection state with both ends on one agent.
