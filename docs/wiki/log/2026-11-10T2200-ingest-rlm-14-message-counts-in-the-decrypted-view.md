## [2026-11-10] ingest | RLM-14 Message counts in the decrypted view

The realism runner has a ninth check, `messages`, and the report format is 0.11.0. The labels file gained an optional `messages` section: a list of rules, each with a `protocol` (`http1`, `http2`, `smtp`, or `imap`), the match fields of a session rule, and `expect` with the counts that every selected session must show. `requests` and `responses` are for HTTP, `messages` (RFC 5322 messages), `commands` by name, and `replies` by SMTP code or IMAP status are for SMTP and IMAP, and a count is a number or a range with `min` and `max`. tshark reads the counts from the capture, or from the decrypted view when `python3 -m realism decrypted` runs the check, one run for each protocol. A session outside its range fails with a named reason such as `missing smtp message: found 0, expected 1`, and so does a rule that matches no TCP session and a missing tshark. `decrypted` prints the first five reasons under `messages:`.

This brings back what MOD-22 dropped with the module copies of `decrypted_check.py`: the request and response counts of http1 and http2 inside TLS, the SMTP command and reply sequence with its message, and the IMAP command sequence with its `BODY[]` literals. The four example labels in `realism/examples/decrypted/` carry the literal counts of the committed fixtures: http1 one request and response on the ports 8443 and 8445 and four on 8444 and 8446 (200 of each in 80 sessions), http2 seven on 8443 and two on 8444 (180 of each in 40 sessions), smtp per session two EHLO, one AUTH, MAIL, DATA, and QUIT, two RCPT, six replies 250, one each of 220, 235, 354, and 221, and one message, and imap per session one CAPABILITY, LOGIN, SELECT, and LOGOUT, three FETCH, seven replies OK, and two messages (the 16 literals in 8 sessions). `tests/test_messages.py` runs them with the real tshark 4.2.2 on the committed fixtures, which pass, and on the same views with one session cut in half, which fail with `missing` reasons, and it needs no nDPI.

Not brought back, because they are not message counts and stay with the modules: the Zeek `conn.log` check of the imap view and the Zeek message check of the smtp view (`modules/smtp/fixtures/zeek_check.py`).

Findings: the labels file stays at `version: 1`, because every section is optional and the new one changes no other, as for the sections of RLM-04 to RLM-09. The count of a message is the occurrence of the tshark field `imf.from`, which RFC 5322 requires, and not `imf.message_id`, which the old script used. An HTTP/2 interim response (1xx) would count as a response. The sandbox has nDPI 4.2.0, so the http2 view fails the conformance check here (no HTTP/2 in nDPI before 4.14), while its `messages` check passes; CI has 4.14.
