## [2026-11-10] ingest | CON-19 Contract gaps found by CAP-02 and RLM-06

We closed the four gaps that CAP-02 and RLM-06 found, with additive changes only. The scenario contract moves to v0.6 and adds the core functions `int_bytes(value, width, endianness)` and `now(format)` (`http_date`, `epoch_s`, `epoch_ms`). `now` reads the clock, so the contract says that goldens and replays pin it and that its output length is fixed, and neither function draws from the seeded generator. The contract also states the rule for variables across `after`: a flow sees the variables of the flows before it on the same role, and the two roles share none during a run, which the engine already does. The test configuration moves to v0.3 and gains optional `arrival` and `size` distributions on the profile and on each mix entry (`constant`, `exponential`, `uniform`, `lognormal`, `pareto`, with the parameter names of the scenario `delay` and of the RLM-06 targets). The metric catalog moves to 0.3.0 with the `application` value `all` and the `property` value `both`, and the module name `all` is reserved. The validator, new tests in `tools/contracts`, the README, the CHANGELOG, the [Contracts](Contracts.md) page, `contracts/changes/CON-19.md`, and the three embedded controller copies carry the change, and `ui/src/api/schema.d.ts` is regenerated. The evidence is `docs/handoff/CON-19.md` and `tools/contracts/test_contracts.py`.

### Shared page notes

The rule for variables across `after` needs no engine change, and an ENG test could pin it.
- [Capture](Capture.md): the notes that there is no clock function and that combined scenarios use `spawn` can change once the engine accepts the functions, because CAP-02 can then emit `int_bytes`, `now`, and `after`.
- [Realism](Realism.md): the temporal check can read its targets from `profile.arrival` and `size` of the test configuration and emit the `all` and `both` series. `realism/schema/realism-report.schema.json` needs the new values.
- [Controller](Controller.md): the compiler decodes the test configuration with `KnownFields(true)`, so a configuration that declares `arrival` or `size` passes the schema and fails in the compiler until a CTL package accepts the fields. The `coreResult` table of the registry can gain `int_bytes` and `now`.
- [Implementation Plan](Implementation-Plan.md): CON-19 leaves four follow ups, which are ENG (functions and clock), CTL (compiler fields and result types), RLM (targets from the test configuration), and CAP (use the functions).
