## [2026-11-10] ingest | MOD-06 HTTP/2 module

We added the manifest, four scenarios, tests, and a fixture to the `http2` module. The scenarios are `h2c_browse` (port 8082) and `h2c_upload` (8081) with prior knowledge, and `https_browse` (8443, `chrome-136`) and `https_upload` (8444, `firefox-139`) over TLS 1.3 with ALPN `h2`. They show six concurrent streams with interleaved DATA frames, browser shaped SETTINGS with `SETTINGS_ENABLE_PUSH` 0, WINDOW_UPDATE flow control, PING, and a graceful two step GOAWAY. We also added `mk/mod-http2.mk` and `.github/workflows/mod-http2.yml` (GitHub-hosted runners only) with the module, harness, and 60 s fuzz jobs. The evidence is `docs/handoff/MOD-06.md` and the module README: tshark 4.2.2 parses all 80 sessions of the capture without parser errors, `decrypted_check.py` decrypts 40 of 40 TLS sessions and counts 180 requests with 180 responses, the `h2` crate accepts both directions of every scenario, and nDPI 4.14.0 (built in the workflow, run on GitHub Actions) classifies 40 of 40 cleartext sessions and 40 of 40 decrypted sessions as HTTP2. nDPI 4.2.0 has no HTTP/2 protocol and reports the cleartext sessions as Unknown. We described the module in [Modules](Modules.md#the-http2-module).

### Shared page notes

- [Modules](Modules.md): the table row and the http2 section are updated in this package.
- Agent registry (AGT-16): `engine/fps-agent/src/modules.rs` needs the `Http2` entry that the MOD-05 note describes (`Registration { name: fps_module_http2::MODULE_NAME, catalog: || catalog_of!(fps_module_http2), build: ... Box::new(fps_module_http2::Http2::default()) }`, and the dependency in `engine/fps-agent/Cargo.toml`). We did not touch `engine/fps-agent`.
- Agent TLS profiles: the https scenarios name the server profile `server-tls13-h2`, which is TLS 1.3 only and selects ALPN `h2`. `engine/fps-agent/src/tls.rs` has only `server-tls13` and `server-tls12`, which select `http/1.1`, so the agent needs a `server-tls13-h2` profile and the browser profiles `chrome-136` and `firefox-139` (the fixture harness registry in `modules/http2/tests/common/tls.rs` builds it).
- Testing and CI, `realism.yml` (outside this package): `realism/ci/install-tools.sh` installs `libndpi-bin`, which is nDPI 4.2.0 on ubuntu-24.04. That nDPI has no HTTP/2 protocol and labels every cleartext h2c session Unknown (with `-d`), so the job `module (http2)` of `realism.yml` fails the `http2` conformance check (0 of 40) until the install builds a newer ndpiReader. The `mod-http2` workflow does it: it builds nDPI tag 4.14 (verified on Actions: `ndpiReader -H` lists HTTP2, 40 of 40 cleartext and 40 of 40 decrypted sessions classify as HTTP2) and selects it with `FPS_NDPI_REAL_READER` and the wrapper `modules/http2/fixtures/ndpi_reader_compat.py` as `FPS_NDPI_READER`, because the `-C` flow file of nDPI 4.14 uses `|` as the separator and `ndpiReader -h` ends with 1, which `realism/classifier.py` does not accept. The owner can move this into `install-tools.sh`, or teach `parse_ndpi_csv` the `|` separator (it also needs `ndpiReader -h` exit codes to be tolerated). The Testing page needs the rows `lint-mod-http2`, `test-mod-http2`, `fuzz-mod-http2`, and `e2e-mod-http2`. `make test-mod-http2` skips the fixture score when tshark or an ndpiReader that lists HTTP2 is missing.
- Zeek: the HTTP analyzer of Zeek 9.0.1 starts on port 8080 and reported one parser error per h2c session there, so the cleartext scenarios use ports 8082 and 8081. Zeek has no HTTP/2 analyzer, so it ignores h2c on other ports.
- nDPI and the client first rule: nDPI detects HTTP2 on a cleartext flow only when the client sends first. With the server SETTINGS ahead of the client preface, 26 of 40 flows were classified. Every scenario server therefore waits for the 24 octet preface.
- TLS module bug (outside this package): `TlsSession::poll_fill` in `modules/tls/native/src/session.rs` fails with "received plaintext buffer full" when one 16.5 KiB chunk of ciphertext completes more than 16 KiB of plaintext while the earlier plaintext is unread. Large bursts over TLS fail. Our https scenarios run with small bodies in tests and fixture (`--var-tls`). The fix is to treat that rustls error as backpressure: stop reading, keep the unconsumed ciphertext, and retry after the application drains the plaintext.
- Cargo.lock: the file gains the dev dependency entries of `fps-module-http2` (`fps-backend-kernel`, `fps-golden`, `fps-module-tls`, and `rustls`).
- Catalog summaries: seven function summaries in `modules/http2/native/src/catalog.rs` were shortened to 200 characters, the limit of the manifest schema. Names, parameters, types, and defaults did not change.
