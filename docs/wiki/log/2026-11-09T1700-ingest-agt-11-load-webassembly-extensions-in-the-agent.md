## [2026-11-09] ingest | AGT-11 load WebAssembly extensions in the agent

The agent now runs the `extension.wasm` of a plan module. `modules::load` checks the tree digest and the signature of each module first, then calls `ExtensionSet::load_module_dir` and keeps one shared `Arc<ExtensionSet>` in `LoadedModules::extensions`, which `assemble` sets as `FlowRef::extensions` on every flow, so the TCP workers of `fps-runtime` use it without more code. The UDP session loop of the agent wraps its native functions through `ExtensionSet::session_functions` with a `SessionKey` and calls `finish` with a `CloseReason` after the outcome is recorded. A module without `extension.wasm` costs one stat call and starts no engine. An extension that does not compile or whose catalog differs from the manifest refuses the plan at prepare with `ModuleError::Extension`, which maps to `FAILED_PRECONDITION`. The extension is part of the module tree, so the tree digest and the signature of AGT-04 already cover it, and `tests/extensions.rs` shows that a changed `extension.wasm` fails the digest check. The test runs a plan with TCP and UDP scenarios over the WAT component of `fps-wasm`: good sessions succeed on both sides and every session of the looping scenarios fails with `extension_error` only. We added the section [WebAssembly extensions](Agent.md#webassembly-extensions) to the Agent page. The evidence is `docs/handoff/AGT-11.md`.

## Shared page notes

- [Engine](Engine.md), `fps-runtime` row and the section on extensions. The agent is now the first user of `FlowRef::extensions` outside the runtime tests, and the UDP path of the agent no longer lacks it.
- Follow up for `fps-runtime` (ENG). `close_reason` is `pub(crate)`, so the agent repeats the mapping from a session outcome to `CloseReason` in `udp.rs`. Export it, and the agent can drop its copy. Also `SessionExtensions::open` fixes the transport at `Transport::Tcp`, so a UDP session tells its extension `tcp`. `SessionKey` needs a transport field, or the wrapper needs to read the flow's `l4`.
- Follow up for AGT-12 (`NativeFunctions` registry). `modules::load` removes the note `module X has no native functions in this agent, so its template calls fail` for a module with an extension, using the helper `no_native_functions`. A registry that replaces `for_modules` should take the set of extension modules, and `for_modules` still refuses settings for a module without native functions, extension or not.
- Follow up for AGT-12/13 and MOD. The extension limits are `fps_wasm::Limits::default()`. A plan or agent setting for the fuel and memory limits needs a contract field, which would be a CON change.
- Follow up for the contract (`contracts/README.md`). A module extension can fail a plan at prepare with `FAILED_PRECONDITION`, which the module install check of the controller does not catch, because the controller does not compile `extension.wasm`. A controller side compile check at install would give an earlier error.
- `Cargo.lock` gained `fps-wasm`, `wat`, `wit-component`, and `wit-parser` as dependencies of `fps-agent` (all already in the lock for other crates), and `fps-agent` has the dev dependencies the tests of `fps-runtime` have.
- A residual race: the agent checks the digest of the module tree and then `ExtensionSet::load_module_dir` reads `extension.wasm` again from disk. A process that can write the modules directory can swap the file in between. The same holds for the scenario and manifest reads of the loader, so a modules directory must not be writable by others. Reading the file once and digesting those bytes would close it.
