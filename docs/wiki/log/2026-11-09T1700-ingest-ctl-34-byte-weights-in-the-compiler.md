## [2026-11-09] ingest | CTL-34 byte weights in the compiler

For `profile.basis: bytes` the compiler (`controller/internal/compiler/`) now turns the byte weights into session shares with the manifest `expected_bytes` of each scenario: `share_i = (weight_i / bytes_i) / sum_j (weight_j / bytes_j)`. The worker rates of a `throughput_bps` objective follow from the weighted mean bytes per session of these shares, so sessions at the compiled rates carry the byte weights and the objective when the estimates are right. A scenario without a positive finite estimate fails the compilation with `ErrNoByteEstimate` for the bytes basis, whatever the objective: a silent fallback would run another mix than the test asks for, and the mix control needs the estimate. The sessions basis is unchanged, and its goldens are byte identical. `newByteMix` in `controller/internal/runs/bytemix.go` takes the compiled weight as the session weight and the compiled weight times the estimate as the byte weight, which gives back the configured byte weights, so mixcontrol keeps its target and starts from the compiled mix. The golden `enterprise_mix_10g` (the only example with basis bytes) shows the converted shares 0.0827, 0.6875, and 0.2298. The new test `TestByteMixExactEstimatesStartOnTarget` shows byte shares within 2 points from the first window with exact estimates, and `TestByteMixConvergesAndStays` still converges from wrong estimates. The [Controller](../Controller.md) page describes it in plan rule 1 and in the byte weighted mix control section.
