## [2026-11-10] ingest | CAP-02 Scenario generation from sessions

We added `python3 -m capture scenario`, which turns a CAP-01 sessions document (with payloads) into a module directory of `manifest.yaml` and one scenario per session, with client and server flows. Each turn is a `send` and an `expect` that matches by a delimiter or a length derived from the data. Field detection replaces Content-Length and chunked sizes, random tokens, UUIDs and transaction ids that repeat across a request and response, HTTP dates, epoch timestamps, and cookies that a later request echoes. Every heuristic has a false positive guard, and the generator renders each template again and falls back to literal bytes when the length does not match. All 608 sessions of the module fixture captures generate scenarios that validate and whose modeled byte counts are exact. The replay with the real `fps-agent` (loopback mode) gave equal byte counts, and the namespace mode runs in CI. We described the command, the heuristics, the limits and the replay job in [Capture](Capture.md). The evidence is `docs/handoff/CAP-02.md`, `capture/tests/test_fields.py`, `capture/tests/test_scenario.py`, and `capture/tests/replay.py`.

### Shared page notes

- [Testing](Testing.md): `capture/tests/test_replay_harness.py` needs root, `tcpdump`, `ip` and the `fps-agent` binary, and skips without them. `cap.yml` does not run it. The job to add (namespace mode) is on the Capture page, under Replay test.
- [Implementation Plan](Implementation-Plan.md): CAP-03 must scrub captures before a scenario is valid, because the default manifest of CAP-02 records `source: capture` with `scrubbed: false`, which the schema rejects. CAP-04 reads the same sessions document and is not affected.
- Contracts: the core template functions have no integer to bytes function (so a binary length prefix stays a literal), no clock function (so an HTTP date becomes a scenario variable), and the contract does not say whether `after` carries variables (the generator uses `spawn`, which does). The validator strips placeholders and then rejects a remaining `{{` or `}}`, so literal braces next to a placeholder have to be written as `hex(..)`.
