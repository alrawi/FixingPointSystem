## [2026-11-07] ingest | ENG-15 failure reasons and side label in the interpreter and runtime

`FailureKind::reason` in `engine/fps-interp/src/failure.rs` now reports `datagram_rejected` for `DatagramTooLarge` and `DatagramMismatch`, `extension_error` for a `Render` failure whose cause is `TemplateError::Function`, and `template_error` for every other render failure. A WebAssembly function failure reaches the renderer as an `FnError`, so it takes the `Function` path and needs no dependency on `fps-wasm`. `fps-stats` gained `SessionCounters::started` and `ended`, and its session counter set now also registers `sessions.concurrent` and `sessions.duration` with the `side` label. `engine/fps-runtime/src/metrics.rs` registers its series through `SessionCounters` with the worker side and no longer loops over `Reason::ALL`. The unit tests in `failure.rs`, the cases in `tests/failures.rs` and `tests/datagrams.rs`, `tests/series.rs` in `fps-stats`, and `tests/loopback.rs` in `fps-runtime` show the three reasons and both sides in a runtime snapshot. The Engine page describes the new mapping. The evidence is `docs/handoff/ENG-15.md`.

## Shared page notes

- [Engine](Engine.md), crate table. The `fps-runtime` row can mention that its session series carry the `side` label.
- Follow up for `engine/fps-agent/` (AGT-07). `src/udp.rs` registers its series by hand without `side` and loops over `Reason::ALL`. It can call `fps_stats::SessionCounters::register` with the side and use `started` and `ended`, and map `fps_interp::Reason` to `fps_stats::FailureReason` as `fps-runtime/src/metrics.rs` does. UDP datagram failures now report `datagram_rejected` instead of `pattern_mismatch`, so any criterion or test there that expects the old reason must change. `src/criteria.rs` still has to select `side=client` by default.
- Follow up for the hook failures of the WebAssembly host. `WasmFunctions::take_failure` exposes the `WasmFailure` of the last failed call, but the render path already maps every function error to `extension_error`. A failure of the `on_data` hook has no interpreter path yet, which the runtime package for extensions (ENG-17) must route to `extension_error`.
