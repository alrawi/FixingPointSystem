## [2026-11-10] ingest | MOD-22 Shared decrypted check in the module capture scripts

The capture scripts of http1, http2, smtp and imap call `python3 -m realism decrypted` now, and the module copies of the decrypted check are gone. Each `capture.sh` was already at the repository root (`cd "$root"`), so `realism` is importable. The commands are the ones of the RLM-12 entry, with the session counts taken from the script: `--sessions $(( sessions * 4 ))` for http1 (four https scenarios), `$(( sessions * 2 ))` for http2 (two https scenarios), and `$sessions` for smtp and imap (one STARTTLS scenario each), which is 80, 40, 8 and 8 at the defaults. Each script writes the result as `MODULE.decrypted.json` beside the capture and keeps the decrypted view as `MODULE.decrypted.pcap` when `FPS_FIXTURE_DECRYPTED_DIR` is set. smtp and imap add `zeek` to `--parsers` and pass `--zeek` when Zeek is installed, as the old scripts did. The exit codes are as before: http1 and http2 exit with the first non zero code of the score and the decrypted check, smtp and imap stop at the first failing check.

Removed: `decrypted_check.py` of the four modules, `test_decrypted_check.py` of smtp and imap, `modules/http2/fixtures/ndpi_reader_compat.py`, and the committed `modules/http1/fixtures/http1.decrypted.json`, whose format was the one of the old script (the next run of `capture.sh` writes the new format to its output directory). The four `tests/fixture.rs` files ran the removed scripts, so they run the shared command now (from the repository root, with the labels of `realism/examples/decrypted/`) and skip when python3 has no PyYAML as well as when tshark or ndpiReader is missing. They no longer assert the message and request counts of the old reports.

Kept: `modules/smtp/fixtures/zeek_check.py` with its tests. It checks the plain sessions of the capture, and `capture.sh` now also runs it on the decrypted view of the STARTTLS sessions (kept with `--view`) with one message and one attachment per session, which the old `decrypted_check.py` did and the shared command does not (it scores only the parser errors of Zeek). `modules/imap` has no other check, and ssh, ftp, dns, pop3 have no decrypted check.

Not covered any more, because the shared command does not do it: the counts of HTTP requests and responses inside TLS (http1 200 and 200, http2 180 and 180), the SMTP command and reply sequence and the message check of tshark inside TLS (smtp), the IMAP command sequence and the 16 literals with an RFC 5322 header (imap), and the Zeek `conn.log` check of the imap view (one TCP connection per session with bytes both ways, no `imap.log` surplus). The command still fails when a TLS session does not decrypt, when the session count is wrong, when the nDPI ratio is below 0.99, and on a parser error of tshark or Zeek on the view.

Nothing ran against the real tools here (the sandbox has no tshark, Zeek or ndpiReader). `bash -n` and `shellcheck -S warning` pass on the four scripts, `rustfmt` on the four tests, and `python3 -m unittest discover -s modules/smtp/fixtures` passes. The proof is the `realism` workflow on the pull request for the four modules.
