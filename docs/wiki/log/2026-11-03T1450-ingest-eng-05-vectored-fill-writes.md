## [2026-11-03] ingest | ENG-05 Vectored writes for fill bodies

We made `send` in `engine/fps-interp/` write large `fill()` bodies as vectored writes from the shared filler, which closes Gate 0 carry over item 1. The new public items are `Template::render_parts`, `Part`, and `Filler::as_bytes` in `fps-flow`, and `VECTORED_FILL_MIN` in `fps-interp`. No existing public item changed. The bytes on the wire and the generator draws equal those of the copying render for the same seed, which unit, component, and property tests check. The criterion benchmark `engine/fps-interp/benches/bulk.rs` repeats the S1 bulk workload, and its paired mode recorded `bench/baselines/fps-interp-bulk-container.json`, where the interpreter reaches 1.17 times the hand written session rate on the same host, against 0.77 for the copying send path. We added the section [Vectored writes for fill bodies](Engine.md#vectored-writes-for-fill-bodies) to the Engine page. The evidence is `docs/handoff/ENG-05.md`, pull request #115, and the tests in `engine/fps-interp/tests/vectored.rs`.
