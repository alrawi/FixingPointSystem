## [2026-11-10] ingest | RLM-06 Temporal distribution check

We added the `temporal` check to the realism report. The runner compares the inter arrival times of sessions (the gaps between their first packets, per application and over all sessions) and the payload sizes (the units of the content check, per application and direction) with target distributions of the labels through the Kolmogorov Smirnov test. A target is constant, exponential, uniform, lognormal, or Pareto, written with the parameter names of a scenario `delay` for arrivals and in bytes for sizes, or an empirical sample, a file of values, or a reference capture. The significance level α is a parameter (default 0.01, `temporal.alpha` or `--ks-alpha`), and a comparison with fewer than `min_samples` observations (default 30) reports `insufficient_data` and fails the check. The entry reports the statistic, the p value, the method, the sample size, the observed spread, and a reason in words. The KS tests are in pure Python (`realism/ks.py`), exact for small samples and asymptotic above that, because the runner has no numeric dependency. The check is opt in, through a `temporal` section in the labels or `--ks-alpha` or `--ks-min-samples`, and the report format moved to 0.7.0. The evidence is `realism/tests/test_ks.py`, which matches the critical value tables and `scipy.stats` values, and `realism/tests/test_temporal.py`, where pcapgen captures from the target pass and captures with a shifted mean gap, a fixed pace, shifted lognormal sizes, or a wrong constant fail. We described the check, its targets, and its limits in [Realism](Realism.md#temporal-distribution-check).

### Shared page notes

- [Implementation Plan](Implementation-Plan.md): the realism report seam is at format 0.7.0 and has the `temporal` entry. The check is opt in, so earlier labels files behave as before. GATE2 and CTL-12 must add a `temporal` section with the target distributions, or pass `--ks-alpha` with one, and the targets must follow the test configuration of the run, because the test configuration has no arrival process or size distribution of its own (load objective and phases only), so the labels author derives them, for example a Poisson process of r sessions per second has exponential gaps with `mean_ms` 1000 / r.
- [Testing](Testing.md): `test-rlm` now also runs `realism/tests/test_ks.py` and `realism/tests/test_temporal.py`, which need no external tool and no workflow change. The check needs no new dependency, and `numpy` and `scipy` stay out of `realism/requirements-dev.txt`.
- Specification: the temporal row of the realism table says that the KS test passes at α = 0.05. The check defaults to α = 0.01, so the gate suite sets α explicitly. The metric catalog has `realism.ks_statistic` and `realism.ks_p_value` with the labels `application` and `property`, and the check emits them per application for `inter_arrival`, `request_bytes`, and `response_bytes`. Comparisons over all sessions and over both directions have no catalog label, because the label `application` is a module name and the property list has no `both`, so a contract change could add them, for example an `all` value for `application`.
- Module realism job: `realism/ci/module-realism.sh` could add a `temporal` section per module once a module fixture records enough sessions, because a short fixture has fewer than 30 gaps and reports `insufficient_data`. No workflow change is needed for this package.
