## [2026-11-10] ingest | CON-22 Realism report delivery and reservation conflicts in the REST API

We added the operation that delivers a realism report to the controller, a documented refusal for a reservation, and the holder of a reservation to the REST contract. `PUT /v1/runs/{id}/realism` takes the realism report as the runner writes it (referenced, not copied), replaces an earlier report as a whole, accepts only a run that has ended, and limits the body to 4 MiB. Each metric of a check becomes one `RealismResult`, so `RunReport.realism` is no longer always empty once a controller serves the operation. `reserveAgent` documents 404 and 409, which the controller already answers for an agent held by another holder, offline, or busy, and `Agent.reserved_by` names the holder. The owner approved the change on 2026-11-10, and every part is additive. OpenAPI moves to 0.10.0. We updated [Contracts](../Contracts.md) and the entry `contracts/changes/CON-22.md`, which lists the consumers (controller, realism runner, CLI, UI, SDK).
