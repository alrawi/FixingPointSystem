## [2026-11-17] ingest | CTL-53 The controller reports kernel release, selected backend, and XDP mode

CTL-53 (issue #597) fills the REST fields of CON-32 in `controller/internal/agents/rest.go`. `Agent.backend` is the backend that the agent selected. An agent that sends `BACKEND_UNSPECIFIED` (agent protocol 0.2.4 or earlier, or no backend that can run) gets the first known entry of `backends`. `Agent.kernel_release` and `Agent.ports[].xdp_driver_mode` are absent when the agent sent an empty string or `XDP_MODE_UNSPECIFIED`. [Controller](Controller.md#agent-view-of-the-host-ctl-53) has the rules.

Decisions.

- The fallback keys on the value, not on the version, because a new agent still reports engine_api 0.2.6 and the controller cannot tell old from new.
- The XDP mode is a driver table hint. The controller copies it and never selects or refuses on it.
- A new agent that lists no backend and selects none has no `backend` property.

Findings.

- `wiring.Inventory` (`controller/internal/wiring`, outside this package) still takes the first known backend of `backends` for the orchestrator, so the compiler does not see the selected backend. This is only a problem once an agent can select a backend other than the first (TRN-12 sets `TRANSPORT_AVAILABLE`). A follow-up in the wiring paths should read the same selected backend.
- No UI or SDK change is needed: `ui/src/api/schema.d.ts` was regenerated by CON-32 and no page reads the new properties yet (UI-06 may show them).
