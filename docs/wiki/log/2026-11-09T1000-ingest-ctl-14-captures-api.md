## [2026-11-09] ingest | CTL-14 captures API

The package `controller/internal/captures/` serves `POST` and `GET /v1/runs/{id}/captures` and the capture download. It starts a capture on every working agent of a running run with `start_capture`, records the state per capture, and on a download ends a capture that still runs, fetches each agent's file with `fetch_capture` and the agent initiated `UploadCapture` call of CON-13, and serves the files as one `application/vnd.tcpdump.pcap` stream. Files live under `<data_dir>/captures` (or a temporary directory). A broken transfer resumes with a new transfer id at the offset held, and a file counts only when its size and SHA-256 equal the end message and the `stop_capture` result. `controller/internal/agents/capture.go` adds `StartCapture`, `StopCapture`, `FetchCapture`, and `UploadCapture` to the manager, with the checks of the session token and the single use transfer id, and the engine_api gates (0.2.0 and 0.2.2). The [Controller](../Controller.md#captures) page describes it.

### Shared page notes

- [Testing](../Testing.md): the capture tests run under `make test-ctl` and `make test-ctl-captures`. They use the fake agent in `controller/internal/fakeagent/capture.go` with options to break, corrupt, or refuse an upload. A test name list for the page: `TestCaptureLifecycleAgainstTheContract`, `TestDownloadResumesAfterAnInterruptedUpload`, `TestDigestMismatchIsRejected`, `TestAgentThatCannotServeTheFile`, `TestOldAgentGetsNoFetchCommand`, `TestUploadCaptureChecksTheTransfer`.
- [Agent](../Agent.md) and AGT-09: the controller side is ready for the agent to serve `fetch_capture`. The agent must open `UploadCapture` after it answered, repeat the `transfer_id`, and send `end.digest` equal to the `stop_capture` digest. The controller refuses a file whose size or digest differs from what `stop_capture` reported, so the agent must keep the joined file unchanged until the download.
- The REST contract has no operation that stops a capture, so the download of a running capture ends it. A `POST /runs/{id}/captures/{capture_id}:stop` or a `ready` state in `Capture` would be a contract change (CON package) if the owner wants a separate step.
- `export_tls_keys` is accepted and has no effect, because `StartCaptureCommand` has no such field and the agent writes the key log lines whenever it has them. A command field (CON package) would let the agent leave them out.
- The `Capture` schema has no way to name which agent a file came from. The download concatenates the files of all agents and lists the agents in `X-FPS-Capture-Agents` and `X-FPS-Capture-Missing`.
- `controller/internal/wiring/wiring_test.go`: `pendingOps` no longer lists the three capture operations, because they now reach `captures.API`.
- No retention exists for stored capture files. A later package (CTL or OPS) should decide how long the controller keeps them and add the removal.
