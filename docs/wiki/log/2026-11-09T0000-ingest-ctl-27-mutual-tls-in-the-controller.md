## [2026-11-09] ingest | CTL-27 mutual TLS in the controller

The controller serves the agent gRPC service over mutual TLS by default. `wiring.New` opens the CTL-15 authority from `pki_dir` (default `data_dir/pki`), the gRPC server uses `ServerTLSConfig` and keeps `PeerCertIdentity`, and a second listener (`enroll_listen`, default `localhost:8445`) serves `POST /enroll` and `POST /renew` over `EnrollTLSConfig`. The new settings are `pki_dir`, `tls_names`, `enroll_listen`, `admin_socket`, and `insecure_plain_grpc`, with the flags `-pki-dir`, `-tls-names`, `-enroll-listen`, `-admin-socket`, and `-insecure-plain-grpc`. The agent manager gained `EndSession`, which the authority calls on revocation, and it refuses a certificate that expired and ends the session of an idle agent whose certificate expired. Operators mint tokens and revoke identities with `fps-controller token` and `fps-controller revoke`, which call a unix admin socket (mode 0600) of the running controller, so the controller stays the only writer of the PKI state. A token mint also adds the identity to the inventory. With certificates `agent_auto_enroll` decides whether a valid certificate for an identity outside the inventory is admitted, and it never admits an agent without a certificate. The plain mode stays behind `insecure_plain_grpc` and logs `INSECURE` warnings. Tests with real TLS show that an agent with no certificate, a certificate of another CA, another identity, or a revoked certificate cannot register, and `TestEndToEndMutualTLS` runs the binary with a Go fake agent through minting, enrollment, registration, revocation, and a new enrollment. The [Controller](../Controller.md#mutual-tls-in-the-controller) page describes the design.

### Shared page notes

- [Image](../Image.md) (IMG-01) says in item 1 of its trust notes that the controller serves plain gRPC until the TLS packages land. That is no longer true, and the image breaks until it follows: the controller of the image (`image/files/etc/fps/controller.yaml` and the unit `fps-controller.service`) now requires mutual TLS on `grpc-listen`, but the agent of the image (`fps-agent-start`) dials `http://` with no certificate, so the pair cannot register. Until AGT-08 gives the agent TLS, the image can set `insecure_plain_grpc: true` in `controller.yaml`, which keeps the old behavior with loud warnings, and after AGT-08 it must write an enrollment token for the agent (run `fps-controller token -agent-id <id>` on first boot, after the controller starts) and pass the CA file from `/var/lib/fps/pki/ca.crt`. The unit passes `-grpc-listen ${FPS_MGMT_ADDR}:8444`, and the controller adds that host to its certificate names, so the image needs no `tls_names`, but it must pass `-enroll-listen ${FPS_MGMT_ADDR}:8445` too and open the port 8445 in `isolation.nft`.
- [Agent](../Agent.md): line 81 ("The controller speaks plain TCP until CTL-15 adds mutual TLS") becomes "The controller requires mutual TLS unless it runs with `insecure_plain_grpc`, so the agent dials `http://` addresses only against a controller in that mode", and line 155 ("Mutual TLS waits for CTL-15 on the controller side") becomes "Mutual TLS, enrollment, and renewal wait for AGT-08, and the controller side is done (CTL-27)".
- [Testing](../Testing.md) and the Makefile: `make test-ctl-tls` and `make lint-ctl-tls` (in `mk/ctl.mk`) run the CTL-27 tests alone, and `make lint-ctl test-ctl` covers them. `TestEndToEndMutualTLS` builds the binary and opens a unix socket and real TLS connections on loopback.
- Edits outside the paths of the package, which the owner asked for and which CTL-27 could not avoid: `controller/internal/app/` gained the five settings, because the YAML keys live in `app.Config` and an unknown key is an error, and the two scripts that start the controller with the real Rust agent (`engine/fps-agent/tests/controller_e2e.sh` and `tests/gates/gate1/run.sh`) set `insecure_plain_grpc: true` until AGT-08.
- Contract and plan: no contract changed. AGT-08 needs the pieces that the Controller page lists under "What the agent must change", and it can read the CA from `pki_dir/ca.crt` or pin the fingerprint that the controller logs as `ca_sha256`.
