## [2026-11-06] ingest | CTL-20 Run reasons, criterion results, and criterion filters

We applied decision D12 items 14 and 19 and closed note 4 of the CTL-09 log entry in `controller/internal/runs` and `controller/internal/report`. The Controller page documents the result in the new section Reasons of the run orchestrator and in the section Label filters and the side default of the criteria and reports.

`Run.reason` is filled at every end that is not a completion, so every failed run carries a reason, and `GET /v1/runs/{id}` serves it for failed and aborted runs. A failing verdict names up to three failed criteria with their reasons. Each criterion of the verdict carries `observed`, `passed`, and `reason` in `GET /v1/runs/{id}` and in the JSON report, with `passed` false and no `observed` for an invalid criterion, through the new field `runs.CriterionResult.Invalid`.

The `where` filter of a criterion selects among the labeled series of a metric. The orchestrator now keeps every labeled counter of every agent in `runs.Outcome.Series`, and `runs.Outcome.RunID` lets `report.Evaluator.RunEvaluator` read the metrics aggregator by run id. The evaluator that decides the run state is therefore the one that builds the report, and histogram criteria such as `sessions.response_time.p99` decide the state of the run as they decide the report. `report.NewAPI` hands its totals source to the evaluator through `UseSeries`, so the existing call in `mountMetrics` connects it and the binary needs no change.

CON-08 gives scenario and transport metrics the `side` label, and a total over both sides counts each session twice. A criterion on a metric with the `side` label whose `where` names no side evaluates the client side only, and `where: { side: server }` selects the server side. The run totals, the report summary, and the metric rows of the report follow the same rule. A series without a `side` label predates it and counts for a criterion without a side. A counter that an agent reports both with labels and without is counted once, through its labeled series, so a snapshot that repeats each run total without labels does not double it.

Golden reports in `controller/internal/report/testdata/` cover a failed run with a reason (`fail`, `degraded`, `labeled`), filtered criteria and a histogram criterion over two sides (`labeled`), and the earlier passing run. The evidence is `docs/handoff/CTL-20.md` on the branch `wp/CTL-20` and the CI run of its pull request. The local sandbox could not download Go modules, so `make lint-ctl test-ctl` ran in CI.
