## [2026-11-16] ingest | TRN-17 TCP stack bench harness with a kernel reference stack

`engine/fps-tcp` is a new crate with a `TcpStack` trait, three workloads, and the kernel loopback TCP as its reference stack. The workloads touch sessions only through `SessionIo`, so a measurement includes the adapter. `session_rate` reports completed sessions per second with p50 and p99 times, `throughput` reports delivered Gbit per second and checks every byte, and `socket_scaling` grows the held sockets in steps and reports the setup rate, the memory per socket, the cost of one poll with idle sockets, and the session rate that a probe sees. The command `cargo run --release -p fps-tcp --example tcp_bench -- ARGS` takes plain arguments and writes an `fps-bench/v1` document of the suite `tcp-stack`. The component page [Transport](Transport.md#tcp-stack-bench-harness) describes it.

The package was re-scoped under D13 on 2026-11-16, because `cargo deny` rejects `smoltcp 0.14.0` and `managed 0.8.0` (license 0BSD, which `deny.toml` does not list), and loosening `deny.toml` stays with the owner. The first worker had built a complete smoltcp adapter, and it is preserved on the branch `wp/TRN-20` with no pull request. TRN-17 now has no smoltcp and no `managed` in any `Cargo.toml` or in `Cargo.lock`, and `cargo deny check` passes. `deny.toml` uses `all-features = true`, so an optional dependency or a feature flag would not have helped. The seam (`TcpStack`), `SessionIo`, the workloads, the clock, and the host facts stayed. The smoltcp adapter and its in memory link moved to TRN-20.

The sandbox runs of the reference stack (2 vCPU, 8 GiB, shared with other workers, an open files limit of 20,000, not the GitHub runner and not fat-nuc) give 14,000 to 35,000 sessions per second at 32 concurrent sessions, about 20 Gbit/s over four uploads on one core, and 0.35 to 0.5 KB of user space memory per socket. The scaling run ended at 19,815 sockets, where the open files limit refused the next socket. The results are committed in `engine/fps-tcp/results/sandbox-2vcpu/` and labelled as results of the reference stack.

Finding, a kernel stack scales by descriptors. Every socket is a file descriptor, so a scaling run ends at the open files limit of the process, and the report lists `open_files_soft_limit`. The workload now treats a refused socket as the end of the run with the steps measured so far, in place of an error that loses them. A host that should reach 1,000,000 sockets needs a limit above 1,000,100. The kernel also keeps socket memory outside the resident set, so `bytes_per_socket` shows only the user space cost of a socket, and the idle poll of a kernel run is zero by construction.

Finding, the draft numbers of smoltcp, which live on `wp/TRN-20`. The draft reached 1,000,584 sockets at 1.59 KB per socket in 64 shards within 35 s, and the poll with idle sockets grew from 15 ns per socket at 16,016 sockets in one shard to 52 ns per socket at 1,000,584 sockets. The scaling is linear in the sockets of a set, so a smoltcp based backend needs many small shards or a flow table of its own.

Finding, two behaviors of the kernel on loopback. A reset reaches the peer after the bytes that arrived before it, so a reader sees the data and then `ConnectionReset`, where an in memory stack discards the data first. The test `abort_resets_the_peer_and_ends_later_operations` reads until the error. The source ports of a client are about 28,000 per server address and port, so the scale workload now puts at most 20,000 sessions on one server port.

### Shared page notes

- [Testing](Testing.md): `test-eng` and the `rust` job of `ci.yml` already run the tests of `engine/fps-tcp`, which are the unit tests, `tests/kernel.rs` (the reference stack through `SessionIo`), and `tests/workloads.rs`. One sentence after the `test-eng` row is enough, for example "`fps-tcp` also has the bench command `tcp_bench`, see [Transport](Transport.md#tcp-stack-bench-harness)". A make target for the small profile would belong in `mk/trn.mk`, which is outside the paths of this package.
- CI runner results (coordinator): this package committed results from the agent sandbox and not from a hosted runner, because a workflow file is outside its paths. A workflow that produces them can be `.github/workflows/trn-tcp-bench.yml` with the trigger `workflow_dispatch`, `runs-on: ubuntu-24.04`, `timeout-minutes: 30`, `permissions: contents: read`, the steps `actions/checkout@v4`, `dtolnay/rust-toolchain@stable`, `Swatinem/rust-cache@v2`, and `cargo run --release -p fps-tcp --example tcp_bench -- --profile small --label "github hosted ubuntu-24.04" --out tcp-bench-small.json`, and an `actions/upload-artifact@v4` step for the file. The coordinator can commit the artifact to `engine/fps-tcp/results/github-hosted/`. It must not name a self hosted runner.
- TRN-20 (owner): the smoltcp adapter waits for the owner to allow `0BSD` in `deny.toml`, or to allow `smoltcp` and `managed` by exception. The branch `wp/TRN-20` holds the working adapter on top of this harness, so TRN-20 rebases it onto the merged TRN-17, restores `SmolStack`, `src/link.rs`, `tests/smol.rs`, the smoltcp flags of `tcp_bench`, and the dependency, and measures it on the same hosts.
- [Module Development](Module-Development.md): none, because the package changes nothing about how a module is written. [Home](Home.md) and [Implementation Plan](Implementation-Plan.md): none.
- `Cargo.lock` gains the crate `fps-tcp` with `fps-io`, `thiserror`, and `tokio`, which the workspace already locks. The lock file has no entry for `smoltcp`, `managed`, `heapless`, `hash32`, `bitflags 1.3.2`, or the `defmt` family, which only the smoltcp adapter needed.
