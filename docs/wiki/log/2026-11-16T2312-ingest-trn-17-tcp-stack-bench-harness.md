## [2026-11-16] ingest | TRN-17 TCP stack bench harness and smoltcp behind SessionIo

`engine/fps-tcp` is a new crate with a `TcpStack` trait, three workloads, and smoltcp as the first stack. The workloads touch sessions only through `SessionIo`, so a measurement includes the adapter. `session_rate` reports completed sessions per second with p50 and p99 times, `throughput` reports delivered Gbit per second and checks every byte, and `socket_scaling` grows the held sockets in steps and reports the setup rate, the memory per socket, the cost of one poll with idle sockets, and the session rate that a probe sees. The command `cargo run --release -p fps-tcp --example tcp_bench -- ARGS` takes plain arguments and writes an `fps-bench/v1` document of the suite `tcp-stack`. The component page [Transport](Transport.md#tcp-stack-bench-harness) describes it.

The sandbox runs (2 vCPU, 8 GiB, not the GitHub runner and not fat-nuc) give about 72,000 sessions per second at 32 concurrent sessions, about 27 Gbit/s over four uploads on one core, and 1.55 to 1.9 KB per socket. The scaling workload reached 1,000,584 sockets in 64 shards within 35 s, with 1.59 KB per socket (about 1.6 GB). The results are committed in `engine/fps-tcp/results/sandbox-2vcpu/`.

Finding, smoltcp scales linearly per poll. smoltcp walks every socket of a set to demultiplex a packet, to find work to send, and to add a socket. A poll with idle sockets costs 15 ns per socket at 16,016 sockets in one shard and 52 ns per socket at 1,000,584 sockets in 64 shards (52 ms for all shards), and a session probe falls from 24,000 per second at 1,544 sockets to about 90 per second at 1,000,584. The memory per socket is flat, so 1,000,000 sockets are a question of poll cost and not of memory. A smoltcp based backend needs many small shards or a flow table of its own, and the adapter already runs one socket set per host for this reason.

Finding, the license of smoltcp. `cargo deny check` (0.21.0) passes bans, sources, and advisories for the new dependencies, and fails the licenses check for `smoltcp 0.14.0` and `managed 0.8.0`, which both carry `0BSD`. `deny.toml` does not list `0BSD`. The license is a permissive one without conditions and is compatible with GPL-3.0, but loosening `deny.toml` stays with the owner under decision D13, so this package does not edit it. Until the owner allows it, the `cargo-deny` job of `ci.yml` is red for any pull request that links smoltcp, including TRN-17.

Finding, two smoltcp behaviors that the adapter handles. A listening socket serves one SYN, so a port keeps `backlog` listening sockets and the adapter replaces each one between two packets of a poll, and a burst of 100 sessions on a backlog of 2 connects in the test `a_burst_larger_than_the_backlog_all_connects`. A socket in TIME-WAIT stays for ten seconds and cannot be shortened, so the adapter removes it at once by default and keeps it with `--time-wait keep`, which `time_wait_sockets_stay_under_the_keep_policy` checks with a manual clock.

### Shared page notes

- `deny.toml` (owner): add `"0BSD"` to the `[licenses] allow` list, or an exception for the crates `smoltcp` and `managed`. This is the only cause that keeps TRN-17 from a green CI, and the owner decides it under D13.
- [Testing](Testing.md): `test-eng` and the `rust` job of `ci.yml` already run the tests of `engine/fps-tcp`, which are the unit tests, `tests/smol.rs` (the adapter through `SessionIo`), and `tests/workloads.rs`. One sentence after the `test-eng` row is enough, for example "`fps-tcp` also has the bench command `tcp_bench`, see [Transport](Transport.md#tcp-stack-bench-harness)". A make target for the small profile would belong in `mk/trn.mk`, which is outside the paths of this package.
- CI runner results (coordinator): this package committed results from the agent sandbox and not from a hosted runner, because a workflow file is outside its paths. A workflow that produces them can be `.github/workflows/trn-tcp-bench.yml` with the trigger `workflow_dispatch`, `runs-on: ubuntu-24.04`, `timeout-minutes: 30`, `permissions: contents: read`, the steps `actions/checkout@v4`, `dtolnay/rust-toolchain@stable`, `Swatinem/rust-cache@v2`, and `cargo run --release -p fps-tcp --example tcp_bench -- --profile small --label "github hosted ubuntu-24.04" --out tcp-bench-small.json`, and an `actions/upload-artifact@v4` step for the file. The coordinator can commit the artifact to `engine/fps-tcp/results/github-hosted/`. It must not name a self hosted runner.
- [Module Development](Module-Development.md): none, because the package changes nothing about how a module is written. [Home](Home.md) and [Implementation Plan](Implementation-Plan.md): none.
- `Cargo.lock` gains `smoltcp`, `managed`, `heapless`, `hash32`, `bitflags 1.3.2`, and the `defmt` family (`defmt`, `defmt-macros`, `defmt-parser`) that the lock file lists for the optional features of smoltcp, plus the crate `fps-tcp`. The merge train regenerates the file when it meets another pull request that changes it.
