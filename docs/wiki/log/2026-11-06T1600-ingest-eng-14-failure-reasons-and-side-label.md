## [2026-11-06] ingest | ENG-14 failure reasons and side label in engine statistics

We added `Side`, `FailureReason`, `SessionCounters`, and `TransportCounters` to `engine/fps-stats/` (`src/series.rs`). They register and record the `sessions.failed` counters for all 12 reasons, including `datagram_rejected`, `template_error`, and `extension_error`, and the session and transport counters with the `side` label of catalog 0.2.0. The tests in `engine/fps-stats/tests/series.rs` show each new reason and both sides in a merged snapshot and in the proto3 JSON, and compare both enums with `contracts/metrics/catalog.yaml`. The catalog contract tests in `tests/catalog.rs` stay green, and the catalog table in `src/catalog.rs` already followed CON-08. We added the section [Side label and failure reasons](Engine.md#side-label-and-failure-reasons) to the Engine page. The evidence is `docs/handoff/ENG-14.md`.

## Shared page notes

- [Engine](Engine.md), crate table. The `fps-stats` row can mention the typed side and reason counter sets.
- Follow up package for `engine/fps-interp/`. `FailureKind::reason` maps `DatagramTooLarge` and `DatagramMismatch` to `pattern_mismatch`, `Render` to `internal`, and no variant to `template_error` or `extension_error`. The catalog says `datagram_rejected` means a datagram that broke the size limit or the stop rule, so the two datagram variants map to `Reason::DatagramRejected`. A template failure maps to `Reason::TemplateError` and a failed module function to `Reason::ExtensionError`, which needs `Render` to separate its template and module causes. The doc comments of the three new `Reason` variants say that `FailureKind::reason` does not report them, and they need an update.
- Follow up package for `engine/fps-runtime/`. `src/metrics.rs` registers its session series without `side` and has its own `Reason::ALL` loop. It can use `fps_stats::SessionCounters::register(shard, module, scenario, side)` with `worker.side` (a `fps_interp::Side`, mapped to `fps_stats::Side`), call `failed` with the mapped reason, and register `sessions.concurrent` and `sessions.duration` with the `side` label too.
- Follow up package for `engine/fps-agent/`. `src/udp.rs` has a second copy of the same registration and needs the same change. `src/criteria.rs` evaluates totals and ratios (`sessions.failed_ratio`, `tls.resumption_ratio`), and with two sides in one run it must select `side=client` unless a criterion selects the server, as the catalog says. Today it sums series without that label.
- Follow up for `controller/internal/metrics/testdata/refgen/src/main.rs`, which registers `tcp.handshakes` without `side`. It stays valid, because a key may omit labels, and it can add `side` when the controller tests need per side reference data.
- No engine code records `tcp.*` or `tls.*` series yet. `TransportCounters` waits for the TRN workstream.
