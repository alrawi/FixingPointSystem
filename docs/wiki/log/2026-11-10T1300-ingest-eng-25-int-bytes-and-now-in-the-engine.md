## [2026-11-10] ingest | ENG-25 int_bytes and now in the engine

`fps-flow` compiles, checks, and renders the two core functions of scenario contract v0.6 (CON-19). `int_bytes(value, width, endianness='big')` writes an unsigned integer as exactly `width` bytes in network or little endian order. A literal argument that breaks a rule fails the load, and a computed one fails the session with `template_error`. The engine never truncates, wraps, or encodes a negative value, and a width of 8 takes 0 to 2^63 - 1. `now(format)` renders `'http_date'` (29 bytes, UTC), `'epoch_s'`, or `'epoch_ms'`, a literal format fixes the result type, and the compiler never folds it. `int_bytes` folds when its arguments are known and valid. The clock is a seam next to the random source: `fps_flow::Clock` with `SystemClock` (the default) and `PinnedClock` (one instant, optional fixed step per call), carried by `RenderCtx` and set with `Session::set_clock` and `ScenarioInstance::set_clock`. `SessionCtx` and `InstanceConfig` did not change, so `fps-runtime`, `fps-agent`, and `fps-backend-kernel` compile as before and run on the wall clock. Fourteen parity fixtures in `engine/fps-flow/tests/fixtures/` (two accepted, twelve rejected) give the same verdicts in Rust and in `tools/contracts/validate.py`. The package also pins the rule for variables across `after` with instance tests: a later flow and a flow behind a chain read what an earlier flow bound, and a client instance and a server instance each see only their own bindings. We updated [Engine](../Engine.md#the-functions-int_bytes-and-now).
