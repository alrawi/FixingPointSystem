## [2026-11-10] ingest | MOD-05 HTTP/2 framing and HPACK functions

We added the native crate `fps-module-http2` under `modules/http2/native/`. It has twenty template functions: encoders for the connection preface, `SETTINGS` and its acknowledgment, `HEADERS` with `CONTINUATION`, `DATA` with padding and `END_STREAM`, `WINDOW_UPDATE`, `PING` and its acknowledgment, `GOAWAY`, and `RST_STREAM`, and readers for a server (`frame_length`, `frame_stream`, `frame_field`, `headers_decode`, `header_value`, `settings_value`, `data_payload`, `data_frames`, `headers_frames`). The HPACK encoder follows a documented policy per field (static table, dynamic table with size updates, Huffman) and the module value keeps one encoder and one decoder per connection side. The evidence is `docs/handoff/MOD-05.md`: the RFC 7541 Appendix C.2 to C.6 vectors, an interop test with the `h2` crate 0.4 in both directions, a catalog test, an interpreter flow test with a scenario that reads frames, and a seeded fuzz loop that ran 461350 rounds in 60 seconds without a panic. We described the module in [Modules](Modules.md#the-http2-module).

### Shared page notes

- [Modules](Modules.md): the page has a table row and a section for `http2`, written in this package. The row says that the module has no scenarios and no fixture yet, because `modules/http2/manifest.yaml` belongs to MOD-06.
- Agent registry: `engine/fps-agent/src/modules.rs` needs a dependency `fps-module-http2 = { path = "../../modules/http2/native" }` in `engine/fps-agent/Cargo.toml` and this entry in `REGISTRY`. `stateless!` does not fit, because `Http2` is a struct with state and not a unit value, so the entry is `Registration { name: fps_module_http2::MODULE_NAME, catalog: || catalog_of!(fps_module_http2), build: |ctx| { if ctx.given.is_some() { return Err(BuildError::Settings("the plan gives settings, but its native functions take none".to_owned())); } Ok(Box::new(fps_module_http2::Http2::default())) } }`. The test `the_module_value_is_clone_send_and_sync` shows that the type satisfies the `NativeModule` bounds. The agent test that lists the registered modules (`["http1", "dns", ...]`) needs the new name.
- Module build files: `mk/mod-http2.mk` and the CI step are not part of this package. The 60 second fuzz test is `cargo test -p fps-module-http2 --release --test fuzz -- --ignored fuzz_60s`, and a workflow step for it is `run: cargo test -p fps-module-http2 --release --test fuzz -- --ignored fuzz_60s --nocapture` in the rust job, or in a scheduled job if 60 extra seconds per push is too much. The short fuzz run, the Appendix C vectors, and the `h2` interop run with `cargo test --workspace` already.
- Cargo.lock: the file gains only the entry of `fps-module-http2`, because every dependency, `h2`, `http`, `bytes`, `tokio`, `rand_pcg`, `serde_norway`, `fps-interp`, and `fps-io`, is in the lock already.
- MOD-06 (manifest and scenarios): `cargo run -p fps-module-http2 --example print_catalog` prints the `functions:` list that the manifest must hold, and `tests/catalog.rs` compares `modules/http2/manifest.yaml` with the native catalog as soon as the file exists. A scenario reads a frame with two `expect` actions and keeps the payload in `last`, because `set` renders to lossy text. `tests/data/h2c_flow.yaml` shows the idiom.
- [Testing](Testing.md): the realism job needs HTTP/2 detection by nDPI and tshark on a cleartext (h2c prior knowledge) capture, which MOD-06 must confirm, because browsers and most servers use h2 over TLS only.
