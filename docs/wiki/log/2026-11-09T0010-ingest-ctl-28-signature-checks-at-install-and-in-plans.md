## [2026-11-09] ingest | CTL-28 signature checks at install and in plans

`Registry.Install` now verifies the signature of a module archive before it unpacks, when the controller has a trust store. The registry copies the archive to a staging file, runs `VerifyArchive`, unpacks the same bytes, and checks that the unpacked tree has the signed digest. A modified archive, an unknown, revoked, or expired key, and a bad or truncated signature fail with `ErrUntrusted`, which wraps the cause from the signing package. A module without a signature fails too, unless the development setting `allow_unsigned_modules` is on. Without a trust store (`trust_store_file`) the registry requires nothing and logs a warning, so existing setups and the example modules keep working. The index entry stores the signature (base64) and the key id, and the compiler copies both into `PlanModule.signature` and `signatureKeyId`. The REST operation reads the signature from the headers `X-Module-Signature` and `X-Module-Signature-Key-Id`. See [Controller](../Controller.md#signature-checks-at-install-and-in-plans) for the rules and the tests.
