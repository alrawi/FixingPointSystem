## [2026-11-10] ingest | ENG-24 TLS per session connectors, instance TLS, and tls metrics

`fps-runtime` builds a client connector for every session when the profile is registered with `TlsProfiles::with_client_factory`, gives every flow of a scenario instance a `TlsUpgrader`, and records the `tls.*` handshake metrics. A session of a factory profile has a fresh resumption store, so it never resumes and its ClientHello keeps the JA4 of its profile against a server that issues tickets. The factory keeps the resumption setting of the profile and does not disable it, because a TLS 1.2 ClientHello without `session_ticket` has another JA4. `TlsProfiles::with_client` stays and stays shared, so existing callers compile and behave as before. `fps_interp::FlowEnv` gained `tls_upgrader(flow, side)` with a default of `None`, and `InstanceEnv` implements it, so a `tls_upgrade` in a spawned flow succeeds. The upgrader collects the `HandshakeReport` of every handshake in a sink that the worker drains into its shard when the session or instance ends: `tls.handshakes`, `tls.resumptions`, `tls.handshake_failures`, `tls.alerts.tx`, `tls.alerts.rx`, and `tls.handshake_time` with the `port` and `side` labels. A handshake that the open timeout cancels counts as a failure through a drop guard. `FlowRef::port` carries the test port name for the `port` label (default `default`). `tests/tls_sessions.rs` checks three sessions with one JA4 (computed with `realism/ja4.py` from a ClientHello that a relay records), a shared connector control whose later sessions resume and change JA4, a spawned flow with `tls_upgrade`, a failed handshake with its alerts, and the series in the proto JSON of a snapshot. We updated [Engine](../Engine.md#tls-upgrade-in-the-runtime).

### Shared page notes

- Agent, for AGT-16 (`engine/fps-agent`, not edited here because AGT-12 edits it). In `tls.rs` `build`, replace `let connector = TlsConnector::new(&profile, roots.clone()).map_err(tls_error)?; profiles = profiles.with_client(browser.name, connector);` with `let roots = roots.clone(); profiles = profiles.with_client_factory(browser.name, move || TlsConnector::new(&profile, roots.clone()));` (validate once with a first `TlsConnector::new` so a bad profile still fails at prepare). Then the server profiles may issue tickets again (`ServerResumption::Tickets` or leave `ServerProfile::default()`), the module documentation section "One connector per session" can go, and the ClientHello shape check of `tests/tls.rs` still holds. In `assemble.rs`, set `flow_ref.port = Some(<test port name of the mix entry>)` so the `tls.*` series carry the `port` label of the plan instead of `default`. The criteria code reads `tls.resumption_ratio` from `tls.resumptions` and `tls.handshakes`, which now exist.
- [Testing](../Testing.md): the `test-eng` row can list `cargo test -p fps-runtime --test tls_sessions`, which needs `python3` (for `realism/ja4.py`) and no other tool.
- `engine/fps-runtime/src/config.rs` carries `#[allow(clippy::large_enum_variant)]` on `Role`: the new `FlowRef::port` field pushed `ServerConfig` over the lint threshold, and boxing the variant would break every caller that builds a `Role`. A package that changes `Role` anyway can box it.
- Follow up for the TLS module (TRN): `TlsConnector` cannot clone itself with a fresh store, so `with_client` cannot become per session. A `TlsConnector::fresh()` that shares the `ClientConfig` pieces and replaces `resumption` would let the registry give a per session connector to the existing API and drop the factory closure from callers.
- Follow up for STATS: `TransportCounters` still registers the three `tls.*` counters for a port and side up front but nothing uses it. The runtime registers its `tls.*` series on demand with `Shard`, because the alert and histogram series have no helper. A helper in `fps-stats` could replace both.
- A client's `tls.handshake_time` runs from the ClientHello to the Finished message, and a server's from the start of `accept`, as `HandshakeReport::elapsed` defines it, so the server value includes the wait for the ClientHello.
